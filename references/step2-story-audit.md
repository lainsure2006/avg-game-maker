# Step 2 — 故事审核（通用标准）

> 本文件是 `avg-game-maker` 8 步流水线的 **Step 2** 模板。
>
> **定位**：审核 **Step 1 产出的故事干净稿 v0.x（叙事层）**，**不是引擎剧本**。
> 剧本化（转引擎指令）是 Step 3，本步只审散文稿的情节 / 逻辑 / 人设 / 节奏 / 情绪。
>
> **通用化原则**：以下 27 项标准与各维度均为**题材无关**的通用框架，
> 适用于纯情 / 恐怖 / 悬疑 / 治愈 / 奇幻 / 自定义任意题材。不绑定任何案例。

---

## 1. 与上下游的关系

- **输入**：Step 1 的 `v0.x_故事干净稿.md` + 填好的设计骨架（角色体系 / 变量机制 / 结局设计）。
- **本步动作**：对照 §3 的 27 项标准逐条审查，产出《审核报告》（§5 模板）。
- **输出**：`故事草稿/审核/审核报告_v0.2.md` → 修订 → `审核报告_v0.3.md`（定稿）。
- **门槛**：Step 2 二审（v0.3）通过，方可进入 Step 3 剧本化。v0.x 干净稿在 Step 2 冻结，
  后续只改剧本指令，不回改叙事正文（避免范围蔓延）。

---

## 2. 审核流程（两轮复审）

| 轮次 | 输入 | 动作 | 产出 |
|------|------|------|------|
| **一审 v0.2** | 干净稿 v0.x | 逐条走 §3 标准，标记 P0/P1/P2 问题 | `审核报告_v0.2` |
| **修订** | v0.2 报告 | 解决全部 P0 + 尽量解决 P1 | 干净稿 v0.x（修订） |
| **二审 v0.3** | 修订后的干净稿 | 复检 P0/P1 是否关闭，扫 P2 | `审核报告_v0.3`（定稿） |

> 规则：**P0 未清零 = 不进 Step 3**。P1 原则上清零；P2 可留作后续迭代备注。

---

## 3. 审核标准（27 项，5 维度通用）

判定列给出**可操作的检查方法**，严重度见 §4。

### 3.1 情节 Plot（6 项）

| 编号 | 标准 | 判定方法 | 严重度 |
|------|------|---------|--------|
| P-01 | 核心目标/冲突清晰 | 能否一句话说清"主角要什么、阻碍是什么" | P1 |
| P-02 | 事件有前因驱动 | 每个关键转折是否由前文铺垫，而非凭空 | P1 |
| P-03 | 无重大情节漏洞 | 关键节点无逻辑断层 / 未解释的机制 | P0 |
| P-04 | 高潮集中爆发 | 核心冲突是否有明确的张力峰值点 | P1 |
| P-05 | 首尾闭环 | 开局设定 / 悬念在结局得到回应 | P1 |
| P-06 | 支线服务主线 | 支线是否推进主题或人物，而非喧宾夺主 | P2 |

### 3.2 逻辑 Logic（6 项）

| 编号 | 标准 | 判定方法 | 严重度 |
|------|------|---------|--------|
| L-01 | 时间线一致 | 事件先后 / 跨度无矛盾 | P0 |
| L-02 | 世界观规则自洽 | 设定（含超自然 / 规则体系）前后统一 | P0 |
| L-03 | 分支条件自洽 | 选择 → 变量 → 结局的触发链无矛盾 | P0 |
| L-04 | 结局可达性 | 每个结局的触发条件在剧情中**可被满足** | P0 |
| L-05 | 伏笔/道具一致 | 关键道具 / 信息不无故消失或凭空出现 | P1 |
| L-06 | 角色能力边界一致 | 角色行为不超出其设定能力 / 权限 | P1 |

### 3.3 人设 Character（6 项）

| 编号 | 标准 | 判定方法 | 严重度 |
|------|------|---------|--------|
| C-01 | 角色动机清晰 | 每个主要角色有可理解的目标与驱动 | P1 |
| C-02 | 性格前后一致 | 关键性格特质无无故翻转 | P0 |
| C-03 | 成长弧线可见 | 主要角色有变化（或刻意的静止设计） | P2 |
| C-04 | 台词符合人设 | 对话口吻 / 用词符合身份背景 | P1 |
| C-05 | 关系演变有铺垫 | 角色间关系变化有渐进过程 | P1 |
| C-06 | 配角非纯工具 | 配角有独立功能，非只为主角服务 | P2 |

### 3.4 节奏 Pacing（4 项）

| 编号 | 标准 | 判定方法 | 严重度 |
|------|------|---------|--------|
| A-01 | 章节起伏 | 张力曲线有波峰波谷，非平铺 | P1 |
| A-02 | 信息密度合理 | 无长时间注水，无单段信息过载 | P1 |
| A-03 | 开局抓人 | 前 1–3 章建立悬念 / 代入感 | P1 |
| A-04 | 中段不拖沓 | 无无效循环 / 重复桥段 | P2 |

### 3.5 情绪 Emotion（5 项）

| 编号 | 标准 | 判定方法 | 严重度 |
|------|------|---------|--------|
| E-01 | 情感曲线有层次 | 喜怒哀惧有积累与递进，非 flat | P1 |
| E-02 | 高潮情感到位 | 关键场景情感冲击充分释放 | P1 |
| E-03 | 结局留余韵 | 结局留有回味 / 思考空间 | P2 |
| E-04 | 基调可控统一 | 整体情感基调与题材匹配，不跑调 | P1 |
| E-05 | 留白与克制 | 关键情感点不过度煽情 / 说教 | P2 |

---

## 4. 严重度分级

| 级别 | 含义 | 处理规则 |
|------|------|---------|
| **P0（阻断）** | 结构性缺陷，影响故事成立或后续可玩性 | 必须清零，否则不进 Step 3 |
| **P1（重要）** | 明显损害体验，但故事可成立 | 原则上清零 |
| **P2（建议）** | 锦上添花 / 风格优化 | 可留作迭代备注 |

---

## 5. 审核报告模板

复制填写。`故事草稿/审核/审核报告_v0.2.md`：

```markdown
# 故事审核报告 — v0.2（一审）

## 项目信息
- 标题：<游戏名>
- 版本：v0.x_故事干净稿
- 审核日期：YYYY-MM-DD
- 审核人：WorkBuddy + 用户

## 维度评分（1=严重问题 5=优秀）
| 维度 | 评分 | 简述 |
|------|------|------|
| 情节 Plot | /5 | |
| 逻辑 Logic | /5 | |
| 人设 Character | /5 | |
| 节奏 Pacing | /5 | |
| 情绪 Emotion | /5 | |

## 问题清单
| 编号 | 维度 | 标准 | 严重度 | 问题描述 | 建议修改 |
|------|------|------|--------|---------|---------|
| 1 | Logic | L-04 | P0 | <结局X触发条件在第N章无法满足> | <调整变量阈值/加铺垫> |
| 2 | ... | ... | ... | ... | ... |

## 结论
- [ ] P0 全部清零（是/否）
- [ ] P1 已处理（是/否/遗留N项）
- 复审判定：<通过定稿 / 需返工修订>
```

`审核报告_v0.3.md`（二审定稿）同结构，附"v0.2 问题关闭情况"小节。

---

## 6. 通用化说明

- 本标准的 27 项与 5 维度**对所有题材通用**，不预设任何故事内容。
- 题材只影响**权重**不影响力项：例如悬疑题材可上调 L-05（伏笔一致）权重，
  恐怖题材可上调 E-04（基调统一）权重 —— 权重由客户在审核时自行侧重，标准本身不变。
- 客户可在 §3 基础上增补题材专属条目，但**不得删减 P0 类通用项**（逻辑/人设一致性是底线）。
