# Step 7 — 游戏测试计划（通用模板）

> **定位**：Step 6 写完游戏后，在 Step 8「完成判定」之前，系统性验证可玩性、表现力、稳定性。
> **本步只测试不开发**（发现 bug 回 Step 6 修）。测试对象 = `npm run dev` 启动后的浏览器实机。
> **通用性**：不绑任何题材；下面所有清单都是「维度 + 复制即用表格」，客户按自己故事填充具体分支名/结局名。

---

## 0. 测试前置（进测试前必须满足）

| 项 | 要求 | 对应上游 |
|---|---|---|
| 构建绿 | `npm run build` **Exit 0**，无 TS 报错 | Step 6 §7 |
| 资源就位 | Step 5 核对报告 P0=0、P1 清零/接受；`MISSING_KEYS` 已清空 | Step 5 |
| 剧本冻结 | `script.ts` 已定稿，分支/结局结构与 Step 3 一致 | Step 3/6 |
| 启动可达 | `npm run dev` 后 `http://localhost:3000` 返回 200 | Step 6 |

> 任一不满足 → 打回对应步，不进测试。

---

## 1. 测试维度总览（7 大类）

| 维度 | 测什么 | 严重度基线 |
|---|---|---|
| A. 冒烟启动 | 构建/启动/标题屏/无控制台报错 | P0 |
| B. 指令执行 | 每条 `ScriptCommand` 类型都能跑、无运行时崩溃 | P0 |
| C. 分支覆盖 | 每个 `choice` 路径可达、变量累加正确、无死分支 | P0 |
| D. 结局收集 | 每种结局 `unlock` 触发、持久化、相册面板/详情弹窗正常 | P0 |
| E. 存档读档 | 中途存档、读档恢复、读档不卡标题屏/不丢背景 | P0 |
| F. 视听表现 | 转场/调色/天气/特效/动画/视频/音频 按计划呈现 | P1 |
| G. 资源渲染 | 无静默空白、立绘比例/站位、背景 cover、N>3 自动布局 | P1 |

> P0 = 阻断（不修不能发布）；P1 = 重要（影响体验，需修或客户接受）；P2 = 建议（锦上添花）。

---

## 2. 测试方法与节奏

### 2.1 三层方法
1. **静态走查**：对照 `script.ts` 逐条读指令，标出「每条 choice 的去向」「每个 label/jump 是否闭环」「每个 if 条件是否都有 else 路径」。
2. **引擎自检（必做）**：开 `npm run dev`，**打开浏览器控制台（F12）**，按 §3 清单逐镜走；任何 `console.error`/红字 = 立即记录（图片静默空白**不报错**，靠肉眼看画面）。
3. **人工目检**：把你（AI）看到的演出与客户的「分镜表/资源总表」逐条比对，挑「大色块、穿帮、不该出现的人、立绘比例怪异」等。

### 2.2 节奏（与客户一起走）
- 第一轮：先走**一条主线到某个结局**，确认能从头跑到 `end`、无崩溃。
- 第二轮：**逐结局走查**（见 §3.D 清单），每个结局至少通一遍。
- 第三轮：**表现力微调**（特效幅度/节奏/补点，见 §4），客户逐条确认。

### 3.C 分支覆盖
| # | 检查项 | 结果 |

## 4. 表现力微调清单（第三轮，客户逐条确认）

> 这部分是「艺术向」而非「功能向」，按客户的反馈迭代，不必一次到位。

| 微调项 | 常见调整 |
|---|---|
| 特效幅度 | flash 透明度、shake 位移量、zoom 倍数 |
| 节奏 | 关键抉择前是否加 `dim` 压暗、告白点 zoom 停留时长 |
| 补点 | 某场景是否缺 `weather:petal`、某高潮是否补 `zoom`/`shake` 示范 |
| 转场选择 | 章节切换用 iris 还是 dissolve、结局用 fade 还是 flash |
| 音频情绪 | 某段是否该换 BGM、SE 是否过多/过少 |

> 例子（来自《樱色未央》待确认项，仅供参考非必做）：街道 `street` 是否补 `weather:petal`；真结局/篮球赛是否补 `zoom`/`shake` 示范点。

## 5. 回归测试套件（防历史 bug 复发）

> 这些坑在引擎迭代中已修，每次新游戏都要复测一遍，避免回归。

| # | 回归项 | 现象（未修时） | 怎么测 |
|---|---|---|---|
| R1 | `loadAudio` 404 崩溃 | 注册了但缺文件的音频 → 启动直接 throw | A4 控制台无 error；manifest 只登记真实文件 |
| R2 | `MISSING_KEYS` 覆盖真图 | 真图放进去仍显示渐变占位 | G1/G2 真图正常显示，占位图仅缺失时出现 |
| R3 | `fadeOutBgm` 音量残留 | 停 BGM 后音量停在 0，后续所有 BGM 静音 | F7 切换 BGM 后能有声 |
| R4 | 读档不退出标题屏/不执行当前指令/背景丢失 | 读档卡标题、黑屏 | E2/E3 走一遍 |
| R5 | 读档转场 artifact | 读档闪一下白/黑 | E4 |
| R6 | `set` 非法 `op:'add'` | 被当 `=` 处理，好感不累加 | C3 |
| R7 | 结局详情弹窗被相册面板压住 | 弹窗点不开/被遮 | D5 |
| R8 | 默认故事无 endings → 结局收集点不开 | 相册按钮无反应 | D1（确保本故事有 endings 或禁用该按钮） |
| R9 | 视频点击跳过冒泡 | 跳过后误触下一句对话 | F6 点击视频后剧情不跳 |
| R10 | `safe-delete` 拦截 `dist` 清空 / `.vite` 删除 | 构建卡死 | A1 构建正常（环境约束，非游戏 bug） |

## 7. 通过门槛与下游衔接

- **进 Step 8 的条件**：A–E 全维度 P0=0；F/G 的 P1 清零或客户书面接受；回归套件 R1–R10 全过。
- **打回规则**：任一 P0 → 回 Step 6 修对应指令/资源，修完重跑本报告，直到通过。
- **衔接 Step 8**：测试通过后，Step 8 做资产终检 + `git tag` 备份 + 发布判定。

## 8. 通用化说明

- 题材只影响「具体分支名/结局名/美术风格」，**不影响测试维度与严重度基线**。
- 客户可增补题材专属检查项（如恐怖游戏加「jump scare 时机」、悬疑加「伏笔回收核对」），但不得删除 P0 基线项。
- 所有「<游戏名>/<结局名>/<分支名>」均为占位，客户按实际填充。
