# Step 8 — 游戏完成判定与交付（通用模板）

> **定位**：Step 7 测试通过后的收尾闸门。判定"游戏是否算做完"，并产出可交付/可备份的成品。
> **本步只验收与归档，不开发、不出图**。所有结论以「清单打勾 + 报告」为据，不靠口头"感觉完了"。
> **通用性**：不绑任何题材；`<游戏名>/<版本号>` 均为占位，客户按实际填充。

---

## 5. 版本备份（D 类，P1）

> 每次"做完一个游戏/一个大版本"必须打 tag，便于回滚与对比。环境约束见 §7 坑注。

```bash
# 在 avg-engine 仓库根目录
git add -A
git commit -m "feat(<游戏名>): 完成 <版本号> 发布版本"
git tag -a v<主>.<次>.<修订> -m "<游戏名> <版本号> 完成备份"
git push origin --tags
```

| # | 检查项 | 结果 |
|---|---|---|
| D1 | 工作区已提交（无未保存改动） | ☐ |
| D2 | 打了语义化 tag（如 `v2.0`）并 push | ☐ |
| D3 | tag 备注写明游戏名 + 版本 + 完成日期 | ☐ |

> **命名约定**：主版本 `.0` = 首个可玩完整版；后续小修小补升 `.1` `.2`；结构性大改升主版本。

## 6. 发布决策（E 类，P1）

| # | 决策项 | 选项 / 说明 |
|---|---|---|
| E1 | 交付形态 | 静态站点（`dist/` 直接托管）✅ 默认 |
| E2 | 托管方式 | 客户自有服务器 / 静态托管平台 / 本地发给客户 |
| E3 | 资源外链 | 全部打进 `dist/`（图片/音频/视频随构建产出，无外部依赖） |
| E4 | 跨域/路径 | `vite build` base 配置正确（相对路径便于任意子目录托管） |
| E5 | 首屏加载 | 资源体积评估（背景 1920×1080、音频 WAV、视频 webm 是否过大需压缩） |

> 引擎 `vite build` 产出静态站点，桌面/移动浏览器通吃，无需后端。发布 = 把 `dist/` 丢到任意静态托管。

## 7. 交付物归档（F 类，P2）

给客户的成品应包含：

| 交付物 | 说明 |
|---|---|
| `dist/` 静态站点 | 可直接打开/托管的最终游戏 |
| 源码 `src/game/story<N>/` | 四件套（客户后续可改剧本/加资源） |
| `<project>/story-wip/` 工作文件 | 故事草稿/剧本化/资源总表/分镜（过程留痕） |
| 测试报告（Step 7） | 验收依据 |
| 本完成报告（Step 8） | 版本/备份/发布结论 |
| 一致性标准文档（G1） | 后续扩充角色/场景的规范 |

> 归档目的：客户后续要加 DLC/新结局/新角色时，有完整规范可循，不会"改一处崩一片"。

---

## 8. 完成定义（Definition of Done）

**齐套判定的硬性门槛**（全部满足 = 本游戏"做完"）：

1. ✅ Step 1–6 全部产出且归档
2. ✅ Step 7 测试报告通过（A–E P0=0、F/G P1 接受、R1–R10 过）
3. ✅ §2 资产终检 A1–A8 全过（无占位图、无静默空白、音频无 404）
4. ✅ §3 构建启动 B1–B4 全过
5. ✅ §4 测试签字 C1–C4 全过
6. ✅ §5 git tag 已打（可回滚）
7. ✅ §6 发布决策已定（客户知道怎么拿到/托管游戏）

> 任意一条不满足 = 不算完成，回去补。

## 10. 通用化说明与收尾

- 题材只影响"具体资产数量/结局名/分支数"，**不影响 DoD 门槛与交付物结构**。
- 客户可增补交付物（如宣传图、玩法说明），但不得删减 §8 七条硬性门槛。
- **8 步流水线到此终结**：Step 1 环境/选材/编写 → Step 2 审核 → Step 3 分镜+剧本化 → Step 4 资源规划 → Step 5 核对 → Step 6 编写 → Step 7 测试 → Step 8 完成判定。后续任何"加角色/加结局/换皮新游戏"都从 Step 1 或对应步重入。

### 收尾提示（环境坑注，非游戏 bug）
- 本环境 `safe-delete` 会拦截 Vite 依赖预优化删 `.vite` 与 `vite build` 清空 `dist`；引擎已配 `optimizeDeps.disabled:true` 和 `build.emptyOutDir:false` 规避，**打 tag 前请确保这两个配置未被回退**（见 Step 7 回归 R10、engine-conventions 坑清单）。
- git 提交用常规 `git add/commit/tag`；大资源（视频/音频）注意仓库体积，必要时 `.gitignore` + 单独资源备份。
