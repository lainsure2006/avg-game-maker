# Step 4 — 资源拆解与合并去重总表（Resource Breakdown & Master Sheet）

> 本文件是 `avg-game-maker` skill 的配套文档，对应 8 步流水线的**第 4 步「拆分剧本 + 统计资源」**。
> 输入是 **Step 3 的分镜表 + 剧本化指令数组**，产出是**合并去重后的资源总表（master sheet）**，
> 它是 **Step 5 资源核对**的直接输入，也为 **Step 6 编写（落位路径 / 登记 manifest）** 提供清单。
>
> **本步只盘点"要什么、要多少、叫什么名、从哪来"，不出图、不写引擎代码。**
>
> 关联文档：
> - 分镜与剧本化字段见 `references/step3-story-board-and-script.md`
> - 角色一致性（**S0 风格与模型选型** → L0 四宫格 → img2img 接入）见 `references/g1-character-consistency.md`
> - 引擎资源键位与出图规格见 `references/engine-conventions.md` 与 `references/engine-asset-catalog.md`

## 1. 定位与作用

| 项 | 内容 |
|----|------|
| 输入 | Step 3 的分镜表（每镜视觉规划）+ 剧本化指令数组（每镜引擎指令） |

## 2. 从 Step 3 抽取资源需求（字段 → 资源类型映射）

一镜 = 一组资源需求。从 Step 3 分镜表按下列映射逐镜抽取：

| 分镜字段 | 映射到的资源大类 | 说明 |
|----------|----------------|------|
| 场景 bg / 时段 / 天气 / CG 标记 | **A. 背景 Backgrounds** | 不同时间段/季节/情况 = 不同背景 key；CG 单独一类 |
| 出场角色 / 位置 / 机位角度 / 表情 / 动作 | **B. 角色立绘 Sprites** | 角度（正/侧/俯/仰）+ 动作 + 表情 决定需要哪些 sprite 键。**必须反查成 `立绘差分清单`（§4.5），只登记 `default` 即漏项** |
| 动画标记 anim | **C. 动画 Animations** | 序列帧；也含 Step 3 第 4 条"动态表情"叠加层 |
| 特效标记 effect | **D. 特效 Effects** | 多数引擎内置（flash/shake/dim/zoom/petal/bokeh…），仅记录参数；自定义需序列帧 |
| BGM 标记 | **E. 音频 BGM** | 由用户下载（AI 音乐/素材站），可空 |
| SE 标记 | **F. 音频 SE** | 由用户合成/下载，可空 |
| 视频过场标记 / 分镜"过场动画"栏 | **G. 视频过场 Video**（引擎已实现 `video` 指令） | 整段 CG 动画、OP/ED，见 §3.7 |
| 物件弹出标记 / 分镜"证物/信件/照片放大"栏 | **H. 物件弹出 Items**（引擎已实现 `item` 指令） | 证物·信件·照片·截图等放大图，无需专门背景，见 §3.8 |

> **Live2D（用户明确不做，仅预留）**：Live2D 是一条**独立于静态立绘的美术/工程管线**——
> 需把角色图**拆图**为分层部位（头/发/眼/眉/嘴/身/臂…各一张透明 PNG）+ 在 Cubism Editor **绑定骨骼**
> （deformer + 父子层级）生成运行时模型，且引擎需集成 Live2D Web SDK。**当前 avg-engine 无 Live2D 运行时**。
> 故本步**只把"未来可 Live2D 化"的角色在立绘子表标 `live2d_eligible` 预留**，不生产 Live2D 资产；
> 实际表现力仍走"静态立绘 + C 类 anim 叠加"（§3.2/§3.3）。若日后真上 Live2D，现有 L0 参考图须改成分层可拆产出（见 §3.9）。

> 抽取时**逐镜扫一遍**，宁可多记不漏记；去重在 §4 做。

## 3. 资源总表 schema（8 大类）

每类一张子表，字段如下。带 `*` 为落位 / 登记必需字段。

### 3.1 A. 背景 Backgrounds

| 字段 | 含义 | 示例 |
|------|------|------|
| `bg_id*` | 背景键（manifest key，也作文件名 stem） | `classroom_eve` |
| 来源分镜 | 哪些镜用到 | ch03-02, ch05-07 |
| 时段/季节/情况 | 决定是否需要单独背景 | 黄昏 / 雪 / 雨 |
| 类型 | 普通背景 / **CG 全屏演出** | CG（见下） |
| 尺寸 | 固定 **1920×1080（16:9）** | — |
| 一致性标准 | 画风/色卡引用（S1） | 日系清新、主色 #xxxxxx |
| 出图方案 | Scheme A/B/C（kickoff 已定） | A.CloudStudio |
| 落位路径* | 引擎实际读取路径 | `public/images/bg/classroom_eve.png` |
| manifest 键* | 登记在 `manifest.backgrounds[bg_id]` | `/images/bg/classroom_eve.png` |
| 状态 | 待出 / 出图中 / 已落位 / 已核对 | 已落位 |

> ⚠️ **两条容易漏的登记约定（2026-09-15 雾港回声核对暴露）**：
> 1. **多角度场景图（pano/2×2）是"约束参考图"，不是引擎资产**。引擎背景要单张 16:9；pano 是 3:1，必须**另做裁切工序**（从 pano 裁 1820×1024 → resize 1920×1080）。别把"参考图做完了"记成"场景已完成"。
> 2. **`manifest` 的图 url 是平面命名空间，多故事共用 `public/`** → 新故事键位可能与已发布故事撞车（实例：story3 占了 `/images/bg/library.png`，新故事的 `library` 会**静默显示成上一部的图**）。
>    **建议：每个 story 一个子目录**（`/images/bg/<story>/<id>.png`）—— manifest 值本就是任意 url 字符串，引擎不关心物理位置，零剧本改动且根治。

**CG 子类（Step 3 第 2 条约束）**：
- 当分镜"不适合人物立绘 + 背景"、需要强表现力时，标为 **CG 类型**：一次性 AI 出全屏图（1920×1080 或更高）。
- 引擎落位同背景通道：注册为 `manifest.backgrounds[<cg_id>]`，剧本用 `scene(<cg_id>)` + 隐藏全部角色显示。
- 文档建议引擎未来加 `scene.kind:'cg'` 或 `cg` 指令以显式区分（当前用 background 通道 + 隐藏角色实现）。
- CG 命名建议 `cg_<scene>_<moment>`（如 `cg_rooftop_confess`）。
- ⚠️ **哪些镜该出 CG 由 Step 3 §2.4「画面呈现形式审核」判定，本步只登记不判定**：
  CG 候选必须**已成清单并经用户拍板**（画什么属审美取舍），且每张须备齐
  **人物参考图 + 场景参考图**两张（缺一就会换脸/场景漂移）。
- ⚠️ **CG 与 `item` 的优先级**：画面主体是"可读的文书/物件" → 走 `item`（H 类），**不要出 CG**。

### 3.2 B. 角色立绘 Sprites（⚠️ 引擎键位关键事实）

> **引擎真实结构（已核对 `game-engine.ts:337` + `types.ts:8,14`）**：
> - `manifest.sprites` 是 `Record<charId, Record<poseKey, url>>`——**只按 `pose` 键位，不含 expression**。
> - 渲染查找键 = `` `${charId}_${pose}` ``。**`expression` 指令字段存在但不参与换图**（仅预留/对话样式用）。
> - **结论**：任何"需要不同脸图的表情/动作" = 一个独立的 `poseKey` = 一个独立文件。
>   例：`linwan_default` / `linwan_happy` / `linwan_sad` / `linwan_surprised`，各自一张 PNG。

| 字段 | 含义 | 示例 |
|------|------|------|
| `char_id*` | 角色 id（与剧本 `char` 指令一致） | `linwan` |
| `pose_key*` | 立绘键（含表情/动作，见上） | `happy` / `side` / `up` |
| 角度 | 正面 default / 侧面 side / 俯 up / 仰 down | 非正面需对应角度图（Step 3 第 3 条） |
| 关联 L0/L1 | 参考源 | L0_linwan + L1_linwan |
| 出图身高基准 | **统一 ~1000px**（否则多人同屏缩放参差，Step 3 第 1 条） | 1000px |
| 落位路径* | `public/images/sprite/<char>_<pose>.png` | `linwan_happy.png` |
| manifest 键* | `manifest.sprites[char_id][pose_key]` | `/images/sprite/linwan_happy.png` |
| 状态 | 待出 / 出图中 / 已落位 / 已核对 | — |

**角度立绘（Step 3 第 3 条）**：分镜标侧/俯/仰机位 → 此处单列 `pose_key=side/up/down`，Step 5 出图时按角度生成。

**动态表情（Step 3 第 4 条）**：基础表情用静态 `poseKey`（如 `linwan_shy`）；关键演出（脸红渐变/震惊睁眼）优先用 **C 类 anim 序列帧叠加**（引擎已支持，`anim play(<id>, <position>)` 渲染在角色层之上），不增立绘文件。

**🔴 立绘登记的常见漏项：只登记 `default`（本项目实测教训）**

只写 `default` 会漏掉**全剧的表情/动作表演**——这是最容易被忽视、又最影响观感的资源缺口。

- **量化依据**：story3（《樱色未央》，已上线）**97 条 `char` 指令中 61 条（63%）是换表情**
  （`default` 36 / `happy` 16 / `smile` 13 / `sad` 10 / `surprised` 3 / `serious` 1 / `worried` 1）。
  → 全程一张 `default` = 角色"面瘫演完整部戏"。
- **正确做法（出图前必做）**：把 Step 3 分镜里**每个角色**的「表情／动作」列**反查一遍**，
  逐条落成 `pose_key`，再按下面的分档取舍。**别只抄 Step 3 摘要里的 `default`。**
- ⚠️ **分镜表可能有多套列结构**（实例：前 6 章用 `人物·动作·表情`，第 7 章起用 `人物(立绘)` + `画面内容`）
  → 写统计脚本时**必须两套表头都兼容**，否则会**静默漏掉后半部所有角色**（本项目踩过）。
- **分档方法（"出场密度 × 情绪跨度"，避免一刀切补图）**：

  | 档 | 判据 | 建议 pose 数 |
  |---|---|---|
  | **A 高频主角** | shot ≥ 10 且跨多章 | 3–4（`default` + 2~3 个情绪/姿态关键点） |
  | **B 关键配角** | 4–9 shot，或承担一个剧情转折 | 2（`default` + 1 个决定性情绪） |
  | **C 单句角色** | 1–3 shot | 1 个 `default` 足够 |

- **姿态类 ≠ 表情类**：分镜写"擦杯／蹲放／对面坐"属**姿态 + 手部动作**，要求**立绘构图装得下手臂**
  （半身到膝即可；**胸像装不下**）。若构图装不下 → 宁可**改分镜**（换成可演的动作，或转 `item` 特写），别硬出。
- **表情差分不是"引擎自动换脸"**：一个 poseKey = 一张独立 PNG。出图时用**该角色 `default` 成品的头部裁切**
  当参考图（head-only，防旧服装传染），提示词**只改神态那一句**，其余身份/服装/机位锚点逐字复制。

### 3.7 G. 视频过场 Video（**引擎已实现**，可直接用）

| 字段 | 含义 | 示例 |
|------|------|------|
| `video_id*` | 视频键（manifest `videos` 的键） | `op_opening` / `ed_trueend` |
| 类型 | OP/ED / 过场动画 / 整段 CG 影片 | 过场 |
| 时长 | 秒（仅规划参考，引擎按视频实际长度播完） | 20s |
| 格式 | 优先 `webm` 或 `mp4`（H.264，浏览器原生解码） | `video_intro.webm` |
| 落位路径* | `public/videos/<video_id>.webm` | `public/videos/op_opening.webm` |
| manifest 键* | `manifest.videos[video_id]` | `/videos/op_opening.webm` |
| 状态 | 待制作 / 已落位 | — |

**引擎接口（已实现）**：`video` 指令 = `{ type: 'video', id }`，全屏 `<video>` DOM 覆盖播放（黑底、object-fit: contain、**点击 = 跳过**、自动播放被拦截则自动跳过不卡死）。播完或跳过后命令循环自动恢复。

**剧本用法示例**（在 `script.ts` 的指令数组里直接加一条）：
```json
{ "type": "bgm", "action": "stop" },          // 过场前停 BGM（视频自带音轨）
{ "type": "video", "id": "op_opening" },     // 全屏播放 OP，播完/点击跳过继续
{ "type": "scene", "bg": "classroom", "transition": "fade" }
```

> 视频过场是**整段预渲染影片**（可由 AI 视频/剪辑产出），不属于引擎实时渲染。manifest 的 `videos` 字段为**可选**，缺失或文件 404 时该指令自动跳过（不卡死）。
> **音频注意**：视频自带音轨；若想过场时静音背景音乐，剧本在 `video` 前显式 `bgm stop`（如示例）。

### 3.8 H. 物件弹出 Items（**引擎已实现**，可直接用）

物件弹出 = 在画面中**弹出该物件的放大图**（证物·信件·照片·截图·报告单等），**无需为此专门出一张背景图**。
引擎用 `item` 指令（`{ type: 'item', id }`）触发：全屏半透明遮罩 + 居中放大 `<img>` + 可选 `caption`（如「匿名信·第七封」），
**点击 = 关闭**，命令循环随后恢复。与 `video` 的关键差异：物件弹窗**不会被自动播放策略/快进跳过**——玩家必须点开细看，
保证关键物证不会一闪而过。图片 404 时显示「（物件图片缺失）」占位仍可关闭、不崩。

| 字段 | 含义 | 示例 |
|------|------|------|
| `item_id*` | 物件键（manifest `items` 的键） | `letter_07` / `report_p18` |
| 类型 | 证物 / 信件 / 照片 / 截图 / 报告单 / 商品图 | 信件 |
| 用途 | 剧情展示 / 收藏解锁 / **变现植入**（见下） | 剧情 |
| `caption` | 可选标题，显示在放大图下方 | 「匿名信·第七封」 |
| 落位路径* | `public/images/items/<item_id>.png` | `public/images/items/letter_07.png` |
| manifest 键* | `manifest.items[item_id] = { src, caption? }` | `/images/items/letter_07.png` |
| 状态 | 待制作 / 已落位 | — |

**剧本用法示例**（在 `script.ts` 的指令数组里直接加一条）：
```json
{ "type": "narration", "text": "信封上没有署名，只压着一枚褪色的校徽。" },
{ "type": "item", "id": "letter_07" },     // 弹出放大图，点击关闭
{ "type": "dialog", "char": "alice", "text": "……这是谁塞进来的？" }
```

**命名规范**：`item_` 前缀（`item_<含义>`）；**变现类物件建议额外用 `ad_` / `shop_` / `dlc_` 前缀**以便 Step 4 分类统计与将来结算：
- `ad_*` — 剧情内植入 / 产品展示（如 `ad_soda_can`）
- `shop_*` — 收藏品 / 周边橱窗（如 `shop_acrylic_stand`）
- `dlc_*` — 付费解锁证物（如 `dlc_secret_photo`）

> 物件图是**单张静态放大图**（透明 PNG 或带底图均可），不属于引擎实时渲染，也不占立绘/背景预算。
> manifest 的 `items` 字段为**可选**；文件 404 时显示「（物件图片缺失）」占位并仍可关闭（**不静默跳过、不崩**），
> 区别于 `video` 的 404 自动跳过。
> **★编辑剧本时的变现切入点**（4 条完整说明 + 前缀规范见 `engine-asset-catalog.md` §J）：植入/产品展示、收藏品橱窗、付费解锁证物、二维码/购买引导图。

### 3.9 预留类（未来扩展）：Live2D

> **用户决定（2026-09-04）：Live2D 暂不做——改动太大**（需拆图 + 骨骼绑定 + 引擎集成 Live2D Web SDK）。本类仅供规划预留，不产资产。

- **Live2D 与静态立绘的本质区别**：静态立绘 = 整张透明 PNG（本方案 B 类）；Live2D = **分层拆图 + 骨骼绑定** 的实时模型。
- **拆图（手工）**：角色图按部位切分为独立透明图层——头、前发、后发、左/右眼（睁/闭/半）、眉毛、嘴（多型）、身体、上臂/前臂、手、衣摆等。通常在 PS / Clip Studio 手工分离，**AI 生图不直接给分层**。
- **骨骼绑定（Live2D Cubism Editor）**：给各部位挂 deformer + 父子层级（呼吸、眨眼、转头、头发飘动），导出 `.model3.json` + 纹理集。
- **引擎集成缺口**：当前 avg-engine 渲染静态 PNG + anim 序列帧，**无 Live2D Web SDK 运行时**，真要做须接入 Cubism SDK（另立大工程）。
- **本步处置**：在 B 类立绘子表对"未来可 Live2D 化"的角色标 `live2d_eligible = true` 即可；**实际表现力仍走静态立绘 + C 类 anim 叠加**（§3.2/§3.3）。
- **未来若真上 Live2D**：现有 L0 四宫格参考图须改为**可分层拆出的产出**（或单独做 Live2D 专用设计稿），否则无法拆图绑定。此点记于此，提醒后续游戏若规划 Live2D 则反向影响 Step 1 美术交付物。

## 4. 合并去重规则

1. **背景**：同一场景不同小时段若视觉可共享（如"教室白天/黄昏"差异大则保留两份；"教室上午/下午"可合并为一份 `classroom`）→ 标注"可复用"避免重复出图。
2. **立绘**：按 `char_id × pose_key` 矩阵去重。一个角色一张 `default` 不重复出；表情只出剧本实际用到的（对应 G1 §4.2 优先级，不铺满）。**去重前先完成 §4.5 的立绘差分清单**（先反查全集，再按档取舍——顺序反了就会漏）。
3. **动画**：相同 anim_id 只计一次；动态表情叠加与静态立绘不重复（见 3.2 末）。
4. **特效**：只汇总"用了哪些类型"，不按镜计数。
5. **视频过场**：按 `video_id` 去重（一场过场一个 id，不按镜计数）；状态标"未制作"时不占实际资产。
6. **物件弹出**：按 `item_id` 去重（同一物件一个 id，不按镜计数）；`ad_`/`shop_`/`dlc_` 变现前缀物件单独统计以便结算。状态标"未制作"时不占实际资产。
7. **音频**：`bgm_title` 无论剧本是否引用都规划（引擎首页自动播放）。规划了但用户未供的，状态标"空"，**不登记进 manifest**。

## 4.5 立绘差分清单（必做产出物 · 对应执行子步骤 4.3b）

> **这一节的由来（真实流程缺陷，2026-09-15）**
> 某部作品照 §3.2 建了立绘子表，但**只登记了每个角色的 `default`**（9 角色 × 1 张），
> 而分镜里明明写着"侧脸""擦杯""手指收紧""平静""蹲放"等 **14 处非 default 需求**。
> 结果 Step 5 核对才发现立绘**缺一整类**，被迫回退补图。
> 根因不是不细心，而是**流程里没有一个"必须产出"的环节**逼你把分镜反查一遍。
> → 本节把它固化为 **Step 4 的强制产出物**：**没有它，Step 4 不算完成。**

### 4.5.1 输入
- Step 3 的**全部**分镜表（不是摘要、不是资源总表）。
- Step 3 的 3a2 画面呈现审核结论（**只有 P1/P2 镜头才是立绘需求**；P3 是 `item`、P4 是 CG，别混进来）。
- 角色分档：主角 / 关键配角 / 单句角色。

### 4.5.2 方法（四步，缺一步都不算做完）
1. **反查**：逐个角色，把分镜里**每一处**「动作/表情」列与「机位」列的描述抄出来（抄原文，先不改写）。
2. **归并**：语义相同的合成一个 `pose_key`（"擦杯"/"擦另一杯" → `default`；"手指收紧" → `tense`）。
3. **分档取舍**：按 §3.2 的 A/B/C 三档决定谁补、补几张（不给单句角色铺表情）。
4. **定名**：给出 `pose_key` + 中文神态说明 + "用在哪几镜"，三者齐备才算定稿。

> ⚠️ **两套表头都要扫**：分镜表前段与后段的列结构可能不同（实例：前段 `人物·动作·表情`，
> 后段 `人物(立绘)` + `画面内容`）。只按一套表头写匹配规则会**静默漏掉后半部所有角色**（本项目踩过）。
> 稳妥做法：写统计脚本时**先把每个分镜文件的表头行打出来人工确认**，再抽字段。

> 🔴 **「备注」列必须一起读**（2026-09-16 实例）：需求常常写在备注里而不是人物列里 ——
> 实例：`| S02 | … | 陆振声(侧) | … | 备注：luzhensheng 仅侧面 |`，反查时只读「人物(立绘)」列
> 就会把 `(侧)` 当成普通出场，**两镜的 `side` 需求整体漏掉**（项目里的惯例是「侧」要独立出 `side` 图）。
> 同理**「画面内容」列**也要读（"老人左手动"这种动作需求只写在那里）。

> 🔴 **反查要在「3a2 呈现形式审核」定稿之后做一次复核**（同实例，2026-09-16）：
> 某镜被升级为 **P4 CG** 后，它**不再显示立绘层** → 原本为它出的差分**瞬间变成冗余**；
> 反过来若某镜从 CG 降级回 P1，就又需要新的脉冲。
> 实例：`luzhensheng_handup` 的唯一消费者（ch11 S05）升级为 CG-04 后，这张图的用途归零。
> ⇒ **凡 P3/P4 判定有变动，都要回头过一遍差分清单的「用在哪几镜」列**，
> 把消费者已消失的行标出来交用户裁掉（别继续为一个无用途的 pose 烧出图预算）。

### 4.5.3 产出物：`立绘差分清单.md`
必须含：
- **结论**一句话 + **量化依据**（例：同项目 story3 的 97 条 `char` 指令中 63% 是换表情 → 一张 default 不够）。
- **角色分档表**（A/B/C + 判据 shot 数/章数 + 建议 pose 数）。
- **逐角色差分表**：`pose_key` | 中文神态/姿态 | 用在哪些镜 | 状态（已有/待出）。
- **出图工艺**：参考图策略、节点链、体检项（可直接引用 `g1-character-consistency.md` §10 与 §3.5）。
- **待决策项**：档位、争议 pose、出图时机。

- ⚠️ **必须交用户选档位**（最小 / 推荐 / 完整 / 超量）——补图量是**预算决策**，不是技术决策。
- 参考图来源逐张写明：**该角色 `default` 成品（已抠图 RGBA 贴白底）裁出的「头 + 颈」** ——
  head-only 防旧服装传染，且**不含构图信息**（构图靠提示词里的实测比例数字重建）；
  🔴 **裁切高度不能写死比例**（"顶部 20%" 会切在脸上 → 输出丢脸），要按**实测肤色底**
  自动定高（钳 `[0.26, 0.34]H）；用 `_gray` 底稿裁会把绿幕背景一起画进成品。
  侧身类用**角色资产表的对应角度列**裁头部（用正面参考配"纯侧脸"提示会出"正脸歪头"），
  同时**不要给宽度数字**（宽度是正面站姿量出来的，与侧身/坐姿天然冲突）。

### 4.5.4 闸门
- 差分清单**未经用户选档** → 不进 Step 5 出图。
- 清单里的 `pose_key` 若无对应图 → **脚本里不得出现该 pose**
  （引擎取不到图会**静默不显示角色**，不报错、不崩溃，只有肉眼能发现）。
  → 要么补图，要么把该镜改回 `default`。

## 5. 命名规范（统一 game 前缀，避免多游戏混库冲突）

| 资源 | 文件命名 | manifest 键 | 说明 |
|------|---------|------------|------|
| 背景 | `{game}_bg_{scene}[_{time}].png` → 引擎内键 `bg_{scene}[_{time}]` | `backgrounds[bg_{scene}]` | 如 `bg_classroom_eve` |
| CG | `{game}_cg_{scene}_{moment}.png` → 键 `cg_{scene}_{moment}` | `backgrounds[cg_...]` | 走背景通道 |
| 立绘 | `{char}_{pose}.png` | `sprites[char][pose]` | 如 `linwan_happy.png` |
| 动画 | `anim_{name}.png` | `animations[anim_{name}]` | 序列帧 |
| BGM | `bgm_{name}.wav` | `audio[bgm_{name}]` | 含 `bgm_title` |
| SE | `se_{name}.wav` | `audio[se_{name}]` | — |
| 视频过场 | `video_{id}.webm`（或 `.mp4`）落 `public/videos/` | 引擎 `video` 指令预留 | OP/ED/过场 |
| 物件弹出 | `item_{id}.png` 落 `public/images/items/`（变现类用 `ad_`/`shop_`/`dlc_` 前缀） | 引擎 `item` 指令 `manifest.items` | 证物/信件/照片/商品图 |

> `{game}` 为该游戏统一前缀（如 `sakura`），仅用于源文件/资产库隔离；**引擎内部键不含 `{game}` 前缀**（见 manifest 示例键值）。
> 命名细则遵循 G1 §7 S3。
> **Live2D（预留，不产资产）**：若未来启用，其分层拆图部件与 `.model3.json` 单独目录 `public/live2d/<char>/`，与 B 类静态立绘互不冲突；当前不登记。

## 6. 图片出图工作流（Step 5 执行，本步只规划）

0. **先跑 S0（G1 §2.5）**：定风格关键词 → **模型选型实验**（同 prompt 同 seed 横比候选模型）→ 沉淀
   Style Block 三段。**换风格必须重跑 S0，禁止沿用上一部游戏的风格词与参数**（混用 = 风格漂移主因）。
1. **逐个给提示词**：背景 / 立绘（及 CG）需逐个写提示词，**按角色·故事风格定制**（非照抄模板，见 G1 §3.4 警告）；
   统一构成 = `STYLE_POSITIVE` + 主体描述 + `STYLE_NEGATIVE`。
2. **用户确认**：提示词给用户确认后再出（kickoff 已定 Scheme A/B/C）。
3. **一致性标准**：S0 之后每个角色出 L0 四宫格（G1 标准第一步）→ 出立绘以 L0 为参考源（img2img 初值法，z-image 默认）。
4. **落位**：出图落 `public/images/bg/` 与 `public/images/sprite/`，文件名按 §5。
5. **CG**：一次性全屏出图，单独走背景通道。
6. **物件/物证图（`item` 弹窗用图）走第二条产线 → `g2-item-art.md`**。
   一句话原则：**AI 只出质感底图，所有文字/印章一律 PIL 叠**（文生图模型画不对中文小字，
   而物证常常是剧情戏眼）。分类 §3 的「物件图」在规划阶段就要按这张表拆：
   纸张类型 / 有无表格格线 / 需要叠哪些字 / 需不需要照片内嵌。
   ⚠️ 规划阶段就要把这些道具的**文案逐字摘录**（放 `item_texts.py`），不要留到出图时现编——
   文案与排版解耦后，改台词不用重出底图。

> 出图方案细节与云端坑见 `SKILL.md` 的 "Asset Generation" 节 + `references/engine-conventions.md`。

## 10. 与用户沟通节点（本步结束前必做）

1c. **确认画面呈现形式审核结论**（Step 3 §2.4）：CG 候选清单 + 用户已拍板；每张 CG 的双参考图来源已定。

3. **确认出图方案**：Scheme A/B/C（kickoff 已定），本步只规划不执行；模型以 S0 选型结论为准。
4. **确认音频缺口**：哪些 BGM/SE 用户能供、哪些留空（留空 ≠ 崩溃，按 §7 处理）。
