# Step 1 — 故事设计（通用骨架）

> 本文件是 `avg-game-maker` 8 步流水线的 **Step 1** 模板。
>
> **定位：我们只提供结构框架与机制范式，不预置任何题材内容。**
> 下一个游戏是纯情、恐怖、悬疑、治愈、奇幻，还是客户自定义题材，由客户决定；
> 本骨架对所有题材通用。本 skill 是 AVG 开发**工具链**，不是内容生成器。

---

## 0. 工具定位（贯穿全 skill 的第一原则）

- 本 skill 提供的是 **结构容器 + 机制范式**，填空的是客户的创意，不是我们的预设。
- 任何"题材要素清单"都是**可选思考提示**，非强制项 —— 客户按需取用，保留发挥空间。
- 引擎能力目录（`engine-asset-catalog.md`：转场/调色/天气/特效/动画）是**能力菜单**，
  不是必选项 —— 客户可以用，也可以不用，我们不下"应该用"的结论。

## 1. 设计骨架字段表（通用，所有题材共用）

| 字段 | 作用 | 客户填什么 |
|------|------|-----------|
| **标题** | 项目标识 | 客户定 |
| **一句话定位 (pitch)** | 锚定基调 | 1 句话说明"这是什么游戏" |
| **目标体量** | 控制规模 | 字数（建议 3–4 万不注水）/ 章节数 |
| **题材** | 分类 | 纯情 / 恐怖 / 悬疑 / 治愈 / 奇幻 / 自定义 |
| **美术风格** | 视觉调性 | 客户定（引擎无关：日系 / 厚涂 / 像素 / 写实 …） |
| **世界观锚点（必填）** | 锁定视觉/叙事基线 | 时代（如民国1930s/近未来/中世纪）/ 地域文化（中式北方庄院/赛博东京…）/ 族群面孔（全员东亚/多族混居）/ 服装基线 / **视觉禁项词表（NOT Japanese, NOT modern…）** |
| **情感基调** | 体验目标 | 如"温暖治愈""压抑惊悚""烧脑反转" |
| **主角模式** | 结构决策 | 玩家代入（无名）/ 具名角色 |
| **角色体系** | 人物网络 | 主要角色清单 + 关系描述 |
| **变量机制** | 分支引擎 | 客户定义变量（好感度 / 线索 / 真相度 / 理智 …） |
| **分支结构** | 剧情拓扑 | 分支点 + 汇聚点 + 关键抉择 |
| **结局设计** | 收束 | 结局数 + 触发条件范式 + 隐藏结局 |
| **章节结构** | 节奏 | 章节数 + 每章功能曲线 |

> 字段表是**结构清单**，不是范文。客户逐栏填自己的内容，我们不做题材假设。

## 1.5 固定预设（引擎决定，客户无需填写）

以下项目由引擎能力决定，属于**我们给的最优解**。客户无需决策，也不进字段表。
> ⚠️ **这些规格是"全局出图规范基线"，Step 1 本身不产出任何图片。** 角色/场景资产的实际出图发生在 **Step 4/5 资源阶段**，到那时才引用本节的尺寸与 L0 卡规范。Step 1 只写故事。

### 1.5.1 目标平台
- **Web 浏览器**（桌面 / 移动浏览器均可，响应式容器）。
- 引擎是 TS + Vite，最终 `vite build` 产出静态站点，可直接部署到任意静态托管。

### 1.5.2 设计分辨率与出图规格（最优解）

| 项目 | 值 | 依据 |
|------|-----|------|
| 设计基准 | **1280 × 720（16:9）** | `renderer.ts` 基准坐标 + `styles/main.css` 容器 `max-width:1280px; aspect-ratio:16/9` |
| 画布实际像素 | 容器尺寸 × `devicePixelRatio` | `renderer.resize()` 自动适配，画面等比缩放 |
| **背景图出图** | **1920 × 1080（16:9）** | 留 1.5× 余量，高分屏不糊；不接受非 16:9 |
| **立绘出图** | 透明 PNG，人物高度建议 **900–1100px** | 720 高画面里半身/全身留白合理，立绘自适应缩放 |
| **L0 四宫格卡** | **2048 × 1024（2:1）** | 四格横向排布，见 `g1-character-consistency.md` |
| 序列帧 `anim` | 逐帧同尺寸 PNG，命名带序号 | 见 `engine-asset-catalog.md` |

> 客户不需要选分辨率。除非客户明确要求非 16:9，否则一律按上表执行。

### 1.5.3 标准预留项（引擎标准项目，客户可留空）

这三类是**引擎的标准能力**，默认在任何项目里都要规划；客户没有能力补充时**留空即可，不阻塞流程**。

| 类别 | 引擎指令 | 说明 |
|------|---------|------|
| **背景音乐 BGM** | `bgm` | 含首页 `bgm_title`（引擎 `showTitleScreen()` 自动播放） |
| **音效 SE** | `se` | 环境音、动作音、UI 音等 |
| **角色语音 Voice** | —— | 引擎当前无独立 voice 指令；如需语音，走 `se` 通道或后续扩展 |

**留空规则（重要）**：
- 骨架里**照常列出**这三类清单（Step 4 统计时保留条目），客户后续可补。
- 但 **`manifest.ts` 只登记实际落位存在的文件** —— 引擎 `loadAudio` 遇 404 会 **throw 崩溃**，
  不是安全跳过。规划了但没素材的音频，只能留空在表里，**不能登记进 manifest**。
- 留空的 BGM/SE 在剧本里对应指令也一并省略，运行不受影响。

## 1.6 世界观锁定（强制门禁 · 进入 Step 2 前必须完成）

> ⚠️ **红线（事故复盘）**：《雪见庄·长夜》曾因 Step 1 未显式锁定世界观，直接进入 Step 4/5 出图时，
> 扩散模型按默认审美把"温泉"画成日式旅馆、把人物画成欧美面孔/现代服饰，造成年代与文化割裂，
> **59 张成品全部作废重跑**。教训：世界观锁定是**出图前的硬前置，不是可选项**——宁可慢一步，不可裸奔出图。

### 必须产出的交付物
- `<project>/story-wip/世界观设定.md`：至少锁定以下 6 项（可参照《雪见庄·长夜》范本结构）——
  1. **时代**（硬指标）：如"中华民国·约 1930 年代"；禁公元年号、禁现代基建（电/网/手机）。
  2. **地域与文化风格**：中式北方庄院 / 赛博东京…；**禁日式**（鸟居/神社/榻榻米/和室/和服/ryokan）、**禁现代**（电灯/手机/现代建筑/现代时装）。
  3. **族群**：如"全员汉族东亚面孔"；禁与剧情无关的西方面孔。
  4. **服装基线**：按角色钉死（旗袍/长衫/马褂/黑大衣灰围巾…）；禁现代时装、禁和服、禁西装三件套外观。
  5. **美术基调**：写实 noir / 厚涂 / 像素… 统一调色与颗粒。
  6. **视觉禁项 negative 词表**：`NOT Japanese, NOT kimono, NOT ryokan, NOT modern, NOT anime…`
  7. **室内外场景区分**（防"室内变露天"）：明确哪些场景是**室内**（厅堂/客房/书房/厨房/马厩/车库/地窖/祠堂/邮政所…）、哪些是**室外**（山路/林/门/屋顶/汤池院落）。室内 prompt **严禁暴雪/飞雪/露天/天空**，必须写"四面墙+顶+地面、封闭空间、雪只在窗外"；暴雪/飞雪/体积雾**只用于室外**。出图生成器须按背景 key 把室内/室外分流到不同氛围基调（室内无雪、室外暴雪）。

### 与后续步骤的硬绑定
- **Step 4/5 所有出图 prompt 必须引用本文件**：角色 prompt 注入种族锚点（`Han Chinese person, East Asian facial features`）；
  场景/物件 prompt 注入文化禁项锚点（`NOT Japanese, no torii, no shoji, no tatami, no ryokan, no modern architecture, no neon, no electric light`）。
- 出图脚本（krea2 / qwen 等流水线）应在 prompt 生成阶段**强制注入**这些锚点，并在提交前做**锚点覆盖校验**——缺锚点拒绝出图。
- **室内场景 prompt 落地时必须二次校验**：确认不含 `blizzard / snowfall / open sky / outdoor / 露天` 等词；含则退回修正（参见《雪见庄·长夜》"书桌/书架/床被画到室外雪地"事故）。
- 进入 Step 2 前，客户须确认 `世界观设定.md` 已锁定；未锁定则退回本步补齐，不得带着模糊世界观进入出图。

## 2. 机制范式（通用，与题材无关）

### 2.1 变量系统
- 引擎 `set` 指令：`op` 仅 `'=' | '+=' | '-='`（**没有 `'add'`**）。
- 客户按游戏需要定义任意变量名，例如：
  - `aff_a` 好感度、`clue` 线索数、`truth` 真相度、`san` 理智值、`trust` 信任度
- 变量驱动分支：`if (条件) → jump (标签)`，`label` 定义跳转目标。

### 2.2 分支与汇聚
- **分支点**：关键抉择处设 `choice`，不同选项修改不同变量。
- **汇聚点**：多条线在中段 / 结局前收回主线，避免剧情指数爆炸。
- 推荐规模：**2–4 条主分支 + 若干局部小分支**。

### 2.3 结局门控范式（通用伪代码）
```text
# 结局判定：变量阈值 → 跳转
if 变量A >= 阈值A and 变量B >= 阈值B: jump ending_true    # 隐藏/真结局
elif 变量A >= 阈值A:                    jump ending_a
elif 变量B >= 阈值B:                    jump ending_b
else:                                  jump ending_normal
```
- 用 `unlock` 指令把结局注册进收集系统，按 `storyId` 隔离持久化（见 `engine-conventions.md`）。

## 3. 题材要素清单（可选提示，非必填）

> 以下按题材列出"客户**可能**需要考虑"的要素。**仅作思考触发器**，
> 客户自行决定是否采用、如何采用，也可完全不采用。我们不预置答案。

### 纯情 / 治愈
- 情感弧线（从陌生 → 亲密的关系演进）
- 好感度系统（多可攻略角色时）
- 日常节奏与"高光时刻"设计

### 恐怖
- 惊吓机制（jump scare / 心理压迫 / 未知恐惧）
- 安全感锚点（可暂歇的安全场景）与剥夺
- 理智 / 恐惧数值（可选）

### 悬疑
- 线索 flag 系统（收集 → 解锁真相）
- 真相揭示结构（多层反转 vs 单一揭秘）
- 红鲱鱼（误导线索）

### 奇幻
- 世界观设定（时代 / 地理 / 法则）
- 种族 / 势力关系
- 魔法 / 超自然体系（若有）

### 客户自定义题材
- 自行补充该题材特有的结构要素
