# Step 5 — Asset Reconciliation / 资源核对

> 本文件为**通用模板**，不绑定任何题材。适用于《樱色未央》及之后任意新游戏。

---

## 0. 定位

| 项 | 内容 |
|---|---|
| 输入 | Step 4《资源总表_v1.md》+ 7 张分类子表 + 实际已落位的资源文件（`public/…`）+ 即将填写的 `manifest.ts` |
| 动作 | 逐项核对「总表登记项 ↔ 物理文件 ↔ 引擎 manifest 键 ↔ 剧本引用」四者是否一致、齐备、合规 |
| 产出 | 《核对报告_v1.md》+ 缺项清单（带严重度） |

| 不通过 | 回到 Step 4 补资源 / 修正 `manifest.ts` 键位，复检 |

**边界**：Step 5 **不生产任何资源**（那是 Step 4 / G1 的工作），只做"验收"。发现缺口就退回上游，不在本步补图/补音频。

## 1. 核心认知：引擎对「资源缺失」的真实反应（本步基石）

**先吃透这张表，再谈核对**——不知道缺什么会崩，就不知道该把力气放在哪。

| 资源类型 | 引擎行为（已核对源码） | 表现 | 严重度 |
|---|---|---|---|
| **音频 BGM / SE** | `loadAudio` `fetch` 404 → `resp.ok=false` → **`throw`**（`asset-loader.ts:87-88`） | **整个 `loadManifest` Promise.all reject → 游戏启动即崩溃**，黑屏/卡死 | **P0 阻断** |
| **背景图 / CG** | `loadImage` `img.onerror` → `console.warn` + resolve 空图（不抛错） | **静默**：该场景背景空白/破图，流程不卡但演出残缺 | P1 重要 |
| **立绘 sprite** | 同上；且若 `manifest` 键与剧本 `char.id+pose` 不匹配 → 查找 `undefined` → 不显示 | **静默**：角色不出现，对话框仍在 | P1 重要 |
| **动画帧 anim** | 同上 | **静默**：序列帧缺失 → 该动态表情/特效不播放 | P1 重要 |
| **视频 video** | `playVideo`：`canplay` 失败 / 自动播放被拒 / `error` → 自动 `stopVideo` 恢复 | **静默跳过**：过场未播但流程继续（不崩） | P2 建议 |

> **一句话规则**：**音频缺失会炸全游戏，图片/立绘/动画缺失只静默残缺，视频缺失静默跳过。**
> 所以核对时，**音频是头号红线**，必须逐一确认文件在位且格式可被 `fetch` 拿到；图片类靠"引擎自检"才能发现（控制台不报错，肉眼才看得出空白）。
>
> ⚠️ 但**"文件齐全"只是第一步**——还有一层极易漏掉的检查：**手里那批图，是不是引擎真正要读的那种图？** 见 §6 坑 6。

## 2. 五个核对维度

1. **存在性**：总表每一项，物理文件是否真正落位（路径正确、非 0 字节、非占位破图）。
2. **命名 / 键位四连对齐**：`文件名` ↔ `总表 id` ↔ `manifest 键` ↔ `剧本引用`，四者必须完全一致（含大小写、下划线）。
3. **规格合规**：尺寸/比例/透明/格式符合 Step 4 §5 约定。
4. **引擎可加载性**：按 §1 表分级——音频必须可加载（否则崩），图片类加载后须能在场景里实际显示（键匹配），视频可缺失（跳过）。
5. **一致性（G1 标准）**：每角色 L0 基准卡已出、色卡 S1 已提取、L1/L2 按模板；非成品验收项，但纳入报告备注。

## 3. 严重度分级（资源版，对齐 Step 2 的 P0/P1/P2 语义）

| 级 | 含义 | 典型项 |
|---|---|---|
| **P0 阻断** | 不解决则游戏起不来或关键系统失灵 | 音频登记但文件缺失/格式错（崩）；`manifest.ts` 语法/类型错导致构建失败；命名与剧本严重不符致关键角色/场景全程空白 |
| **P1 重要** | 不崩但演出明显残缺 | 立绘/背景/动画帧缺失（静默空白）；非 16:9 致拉伸变形；立绘身高不统一（>3 人自动布局缩放参差）；poseKey 拼写错致某表情不显示 |
| **P2 建议** | 体验降级但可接受 | 色卡/一致性微调；视频未提供（自动跳过，过场没播）；某非关键 BGM 用通用替代 |

**通过门槛**：P0 = 0 且 P1 清零（或客户书面接受保留）。P2 可入"已知项"带过。

## 4. 核对方法（三层，由浅入深）

### 4.1 静态清单核对（人工 + 可选脚本）
- 打开 Step 4 总表，逐行对照 `public/` 实际文件，打勾「存在 / 命名一致 / 规格达标」。
- 可写个小脚本扫 `public/` 列出文件，与总表 `id` 求差集，秒出"登记了但没文件"清单。

### 4.2 引擎自检（**最权威，必做**）
1. 把核对过的键位填入 `manifest.ts`（音频只在**文件确实在位**时才登记）。
2. `npm run dev` 打开页面 → 打开浏览器控制台。
3. **看控制台有无 `音频加载失败` throw**——有则立即回到 manifest 删掉该音频登记或补文件。
4. 走一遍主线 + 各分支，肉眼检查：背景是否出图、角色立绘是否出现、动态表情/动画是否播放、**有无空白破图**。
5. 图片类缺失**不会报错**，只能靠这步肉眼发现——所以引擎自检不可省。

### 4.3 一致性人工目检
- 把成品立绘与 G1 的 L0 基准卡并排看：脸型/发色/配色是否一致；非正面角度 pose 是否与分镜要求匹配。

## 5. 逐类核对清单（复制即用）

> 每类逐行核对，在「结果」列填 通过 / P0 / P1 / P2 / 跳过。

### A. 背景 / CG（`manifest.backgrounds`）
- [ ] 总表每项均有物理文件（`public/images/bg/<id>.png`）
- [ ] 文件命名 = `bg_<id>` 与总表/`manifest` 键一致
- [ ] 尺寸 **1920×1080 / 16:9**（CG 同）
- [ ] 无意外透明边（背景应不透明，除非刻意）
- [ ] CG 类：`scene(cgKey)` 在剧本对应位置，且已隐藏角色

### B. 立绘（`manifest.sprites[charId][poseKey]`）
- [ ] 总表每个 `{char}_{pose}` 均有文件（`public/images/characters/<char>_<pose>.png`）
- [ ] **透明 PNG**，无白底（否则叠背景会露白块）
- [ ] **统一出图身高基准**（约 1000px）——否则 >3 人同屏缩放参差（Step 3 约束①）
- [ ] 非正面机位分镜（侧/俯/仰）要求的 `{char}_side` 等角度 pose 已备
- [ ] 剧本 `char.id` + `pose` 拼写与 `manifest` 键**逐字符一致**（含大小写）
- [ ] 🔴 **表情差分已核对（最易漏，必查）**：扫剧本/分镜里**所有**角色的情绪与动作描述 →
  与 `manifest.sprites[char][*]` 的键位求**差集**。
  实例教训：总表只登记 `default`，而分镜里早写了 `side` / `calm` / `擦杯` / `蹲放` / `two_paths` 等 → **全部漏项**，
  且因为没有文件，这些镜头会**静默不显示角色**（不报错、不空白提示）。
  另按档核对：高频主角（shot ≥10）应有 3–4 个 pose，只有 `default` 即视为**未完成**。
- [ ] ⚠️ **不要核对 `expression` 字段**：它是**空壳**（`types.ts` 有类型、`script-parser.ts` 会解析，但渲染取图只读 `pose`）
  → 剧本写 `expression: "sad"` **不报错也不生效**。若发现剧本用 `expression` 表达表情，**要改写为 `pose`**。

### C. 动画 / 序列帧（`manifest.animations[id].frames`）
- [ ] 每个 anim id 的帧文件齐全、序号连续（`frame_001.png`…）
- [ ] 帧尺寸一致、同目录
- [ ] 剧本 `anim play(<id>,<pos>)` 引用的 id 已登记

### D. 特效（weather / grade / effect / particles）
- [ ] **无需文件**，但核对剧本所用特效类型在引擎支持范围内：
  - effect：`flash / shake / dim / zoom / petal / bokeh`（+ 转场 7 种）
  - weather：`petal` 等粒子（引擎内置）
  - grade：5 种调色
- [ ] 若剧本用了引擎**不支持**的类型 → 退回 Step 3 改剧本或 Step 6 前扩展引擎

### E. BGM（`manifest.audio[bgm_<name>]`）
- [ ] 文件在位（`public/audio/bgm_<name>.wav/mp3/ogg`）
- [ ] 格式浏览器可解（`fetch` 能拿到；wav/mp3/ogg 原生支持）
- [ ] **`bgm_title` 首页曲**：若引擎约定自动播放，文件必须存在（否则崩）
- [ ] **红线**：规划了但用户未供的 BGM → 状态标「空」，**绝不登记进 manifest**

### F. SE（`manifest.audio[se_<name>]`）
- [ ] 同 E 类规则（文件在位 + 格式 + 缺失不登记）

### G. 视频过场（`manifest.videos[id]`）
- [ ] 文件在位（`public/videos/<id>.webm` 或 `.mp4`）
- [ ] 剧本 `video <id>` 引用一致
- [ ] 缺失/格式错 → **不崩，自动跳过**（过场没播）；核对时确认是「故意空」还是「漏了」

## 6. 关键坑（踩过的红线，写入核对铁律）

1. **音频 404 = 全游戏崩**：`loadAudio` 抛错会炸 `loadManifest`。**任何没文件的音频，manifest 里一个字都不能写。** 这条在 Step 4 §7 已立，此处为核对红线复申。
2. **图片缺失静默**：控制台不报错，只有空白。必须靠 §4.2 引擎自检肉眼发现。
3. **sprite 键拼错 = 静默不显示**：`${char.id}_${char.pose}`，剧本里 `pose:'happy'` 但 manifest 写 `sprites.alice.hapy`（拼错）→ 该角色此姿势永远不出现，不报错。
4. **立绘身高不统一**：>3 人自动布局按图片实际高度算缩放，身高参差 → 同屏大小不一。Step 4 立绘规格已定统一基准，核对时抽检。
5. **视频缺失不崩但过场没播**：别把"没报错"误判为"过场正常"。
6. **「中间产物」≠「引擎资产」（雾港回声 2026-09-15 实测，最隐蔽的一条）**
   - 多角度场景图、人物资产表、物证底图，都是**给模型或排版工序当输入**的中间产物，**不是引擎要读的最终图**。
   - 典型事故：14 个场景只做了 `pano(3072×1024，3:1) + 4 段(768×1024)` 的**约束参考图**（`krea2-scene-sheet` 的产出），就以为"场景已完成"——**引擎背景要的是单张 16:9**。
   - 直接塞 pano 会怎样：引擎 canvas 走 cover 映射（取 max 缩放比）→ 3:1 填 16:9 **横向两侧各裁约 20%，只显示中间约 59%**，构图失控且无声无息。
   - **核对时对每一类资源问一句**：「这张图是引擎**直接读**的，还是给**别的工序当输入**的？」只有前者才配进 `manifest`。
   - 同源混淆还包括：**用户审过 pano 宽图 ≠ 引擎背景已验收**（用户审的是参考图，验收对象不同）。
7. **跨故事键位撞车 —— 静默显示"上一部作品的图"，比缺失更难查**
   - `manifest` 的图 url 是**平面命名空间**，多个 story 共用同一个 `public/`。
   - 实例：story3 已占 `/images/bg/library.png`（学校图书馆）；新故事 ch02 也有 `library`（市图书馆过刊室）→ 裸登记会**显示成上一部的图**：不报错、不空白、就是错的。
   - **检查法**：把新故事每个 `bg`/`sprite`/`item` id，与已发布故事的 manifest 求交集；或直接查 `public/images/bg/` 是否已有同名文件（**注意看图在不在，还要看 mtime 是不是本次的**）。
   - **解法（推荐）**：给每个 story 一个**子目录**（`/images/bg/<story>/<id>.png`）。`manifest` 的值本就是任意 url 字符串，引擎不关心物理位置 → **零剧本改动 + 根治 + 下一部同理**。
8. **规格以「实测实况」为准，不看文档声称值**
   - 模板建议值（背景 1920×1080 / 立绘基准 1000px）与工程实况（story3 = **1280×720 / 400×600**）经常不一致，且会随项目演进漂移。
   - 引擎靠 cover / 按高度缩放适配，尺寸**非硬约束**；真正的硬要求是**同一故事内部统一**（否则 >3 人同屏自动布局缩放参差）。
   - 核对用 PIL 实测（尺寸 / 模式 / RGBA 四角 alpha / 文件大小 / mtime），别抄文档。
   - 📌 可复用脚本：`scripts/reconcile_assets.py`（内置清单 + 差集 + 规格体检，一跑出全表）。

## 8. 衔接

- **通过（P0=0 且 P1 清零/接受）** → 冻结资源，进 **Step 6 游戏编写**（`storyN` 四件套）。
- **不通过** → 回到 Step 4：缺图补图（走 G1 L0/L1/L2）、缺音频让用户补或留空不登记、键位拼错修正 `manifest`。复检直到达标。

> 注：Step 5 与 Step 4 共享同一套命名/键位/规格约定（Step 4 §3–§5），核对即"反向验证"那些约定是否被如实落位。
