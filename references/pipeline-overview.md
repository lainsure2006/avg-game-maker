# AVG 游戏开发 8 步流水线 — 总览与索引（含二级子步骤）

> **本文档是整套方法论的入口**。先用它看清全局与每一步的二级动作，再进具体 `stepN-*.md` 看细节。
> **两级结构**：一级 = 8 个 Step（阶段）｜二级 = 每个 Step 下的子步骤（`x.y`，可直接当执行清单打勾）。
> **通用性**：所有 Step/子步骤均与题材无关；"只做工具，创意归客户"。

**串行主干**：1 → 2 → 3 → 4 → 5 → 6 → 7 → 8
**回退边**：任一门槛不过 → 退回产生该问题的 Step（常见：Step7 发现 bug → 回 Step6；Step5 缺资源 → 回 Step4）
**支线**：G1（角色一致性出图）挂在 Step 4/5 之间执行

> **Step 3 内部有两道闸门**（都容易漏）：
> 1. **3a2 画面呈现形式审核** —— 逐镜判 P1 背景+立绘 / P2 +特效 / P3 `item` / **P4 CG 单图**。
>    它决定整部戏有没有 CG、哪些镜出 CG。**必须在 Step 4 拆资源之前过完**，否则资源表里根本没有 CG 这一项。
> 2. **3b 自检** —— 键位合法 / 分支闭合 / 变量自洽 / 音频只登记真实文件。
>
> **Step 4 内部有一件必做产出**：**4.3b 立绘差分清单**（逐角色反查分镜的动作/表情列 → pose 矩阵 → 用户选档）。
> 只登记 `default` 会让全剧角色"面瘫演完"（实测 story3 里 63% 的立绘调用是换表情）。

## 2. 二级子步骤详解（执行清单）

### Step 1 — 故事设计（文字层，零图像零音频）
| 子步骤 | 动作 | 备注 |
|---|---|---|
| 1.1 环境定义 | 平台=Web；分辨率 1280×720 基准 / 出图 1920×1080 等 | **固定预设，客户不填不决策** |
| 1.2 选材 | 题材、美术风格、情感基调 | 客户填 |
| 1.3 角色体系 | 角色名 + 关系描述（**纯文字名册**） | 本步不出图 |
| 1.4 变量机制 | 好感度等变量；`set` 仅 `= += -=` | 引擎机制约束 |
| 1.5 分支与结局 | 2–4 主分支；**结局 ≥3**；`if`+`jump`+`label`+`unlock` 门控 | 引擎机制约束 |
| 1.6 章节结构 | 章节划分 + 体量（3–4 万字不注水） | 客户填 |
| 1.7 写干净稿 | 产出 `v0.x_故事干净稿.md` | 进 Step2 前客户确认 |

> **Scope guard**：Step 1 只写故事，**零图像零音频**；音频（BGM/SE/Voice）是标准预留项，可空。

### Step 2 — 故事审核（审的是散文稿，不是引擎剧本）
| 子步骤 | 动作 | 备注 |
|---|---|---|
| 2.1 定标准 | 27 项 / 5 维度（情节6/逻辑6/人设6/节奏4/情绪5） | 题材只调权重，不删 P0 基线 |
| 2.2 一审 | 出 v0.2 审核报告，问题分级 P0/P1/P2 | |
| 2.3 修订 | 按报告改稿 | |
| 2.4 二审 | v0.3 复审 | **P0 未清零不进 Step3** |
| 2.5 冻结 | 干净稿冻结为唯一真相源 | |

### Step 3 — 分镜设计 + 剧本化（三个子阶段）
| 子步骤 | 动作 | 备注 |
|---|---|---|
| 3.1 **3a 分镜设计** | 逐镜填：镜头号 / 景别 / 机位角度 / 构图 / 镜头运动 / 时长 / 转场 / 演出意图 | **独立产物，不写引擎指令** |
| 3.2 分镜评审 | 视觉决策单独审（构图/机位先定） | 直接喂 Step4（一镜=一组资源需求） |
| 3.3 **3a2 画面呈现形式审核**（必做闸门） | 逐镜判 **P1** 背景+立绘 / **P2** +特效 / **P3** `item` 弹窗 / **P4** **CG 单图**；CG 候选出清单 → 交用户拍板 → 备**双参考图**（人物 + 场景） | 判据见 `step3` §2.4。**不审的后果：整部戏可能一张 CG 都没有，高潮戏站着念完、主角独角戏只剩一张背景** |
| 3.4 **3b 剧本化** | 把每镜翻译成 `ScriptCommand[]` | 长文拆多条，绝不一条塞整章 |
| 3.5 键位表 | 场景→bg 键、角色 pose、变量体系、BGM/SE 命名 | `00_格式说明与键位.md` |

> **4 条硬约束**（Step3 已落地）：① >3 人自动缩放 → 立绘统一身高 ~1000px；② CG 全屏演出 → AI 一次性出图 + `scene(cgKey)`+隐藏角色；③ 非正面机位 → 需对应角度立绘 pose；④ 动态表情 → 基础用静态 pose，关键演出用 `anim` 序列帧叠加。
> **+1 条闸门**（2026-09-15 补）：**3a2 画面呈现形式审核**必须逐镜过 —— 默认形式（背景+立绘）对"蹲/躺/背对、无人物空镜、主角无立绘的独角戏、>3 人关系构图、回忆闪回、章节情感峰值"这六类镜头是错的，必须显式判成 CG；判完还要**交用户拍板**（画什么属审美取舍）。

### Step 4 — 资源规划（只规划，不出图不写码）
| 子步骤 | 动作 | 备注 |
|---|---|---|
| 4.1 逐镜抽取 | 按分镜表逐镜扫资源需求 | 宁多不漏 |
| 4.2 七大类聚合 | A背景(含CG) / B立绘 / C动画 / D特效 / E BGM / F SE / **G视频过场** | 各一张子表 |
| 4.3 合并去重 | 背景可复用合并；立绘按 `char×pose` 矩阵去重 | |
| 4.4 命名规范化 | `bg_` / `{char}_{pose}` / `anim_` / `bgm_` / `se_` / `video_` + `{game}` 前缀 | |
| 4.5 **S0 风格探索** | 定风格词 → **模型选型实验**（同 prompt 同 seed 横比）→ 沉淀 Style Block | **最先做；换风格重跑，不复用上一部** |
| 4.6 出图提示词 | 逐个给提示词（= Style Block + 主体描述），客户确认后再出 | **S0 之后，L0 四宫格是角色资产第一步** |
| 4.7 音频需求清单 | 客户去下载；可空 | **空项绝不登记进 manifest**（404 崩） |
| 4.8 沟通确认 | 方向 / 一致性标准(S0完成) / 出图方案 / 音频缺口 | 四项确认后冻结 v1 |

> **已确认不做**：Live2D（需拆图+骨骼绑定+SDK，改动太大）→ 仅作预留类标记 `live2d_eligible`。

### Step 5 — 资源核对（只验收，不生产）
| 子步骤 | 动作 | 备注 |
|---|---|---|
| 5.1 静态清单核对 | 总表项 ↔ 文件 ↔ manifest 键 ↔ 剧本引用 四连对齐 | |
| 5.2 **引擎自检**（必做） | `npm run dev` + 开控制台走流程 | 图片缺失**静默空白**，控制台不报错，只能肉眼查 |
| 5.3 人工目检 | G1 一致性（色卡/画风/脸型） | |
| 5.4 严重度分级 | P0 阻断 / P1 重要 / P2 建议 | 音频 404 = P0（整游戏崩） |
| 5.5 核对报告 | 结论 + 缺项清单 + 复检记录 | P0=0 才进 Step6 |

### Step 6 — 游戏编写（四件套）
| 子步骤 | 动作 | 备注 |
|---|---|---|
| 6.1 建目录 | `src/game/story<N>/`（引擎 `./story[0-9]*/story.ts` 自动发现） | 必须数字编号 |
| 6.2 复制模板 + 改名 | 复制 `story-template/` → 改 4 文件命名一致性 | `getManifest` 必须调本目录 placeholder 函数 |
| 6.3 `manifest.ts` | 登记资源 | **只登记真实存在的文件** |
| 6.4 `script.ts` | `ScriptCommand[]` JSON 数组 | 由 Step3 直译；长文拆分 |
| 6.5 `placeholder.ts` | 缺图兜底渐变 | 真图就位后**清空 `MISSING_KEYS`**，否则盖住真图 |
| 6.6 `story.ts` | `StoryDef`；`subtitle` 必填；`endings.id` ↔ `unlock` 一致 | |
| 6.7 构建验证 | `npm run build` Exit 0 + `npm run dev` 起得来 | |

### Step 7 — 游戏测试（实机走查）
| 子步骤 | 动作 | 备注 |
|---|---|---|
| 7.1 静态走查 | 逐条读指令：choice 去向 / label-jump 闭环 / if 双路径 | |
| 7.2 **引擎自检** | `npm run dev` + 控制台开，按 7 维度走 | |
| 7.3 逐结局走查 | 每个结局至少通一遍，确认 `unlock` + 相册可见 | 与客户一起走 |
| 7.4 回归 R1–R10 | 复测历史已修 bug | 防复发 |
| 7.5 表现力微调 | 特效幅度 / 节奏 / 补点 / 转场 / 音频情绪 | 艺术向，客户逐条确认 |
| 7.6 测试报告 | 7 维度评分 + 问题清单 + 回归 + 微调记录 | A–E P0=0，F/G P1 接受 |

### Step 8 — 完成判定与交付
| 子步骤 | 动作 | 备注 |
|---|---|---|
| 8.1 资产终检 | manifest 每项有真实文件；占位图清空 | 最易"假完成" |
| 8.2 构建启动 | build 绿 / dev 200 / 无 console error | |
| 8.3 测试签字 | Step7 报告通过 + 客户确认 | |
| 8.4 git tag | 语义化版本 `v<主>.<次>.<修订>` + push | 可回滚 |
| 8.5 发布决策 | 静态 `dist/` 托管；资源体积评估 | 无需后端 |
| 8.6 交付归档 | dist + 四件套源码 + story-wip + 报告 + G1 一致性文档 | |

## 3. 支线：G1 角色一致性出图（挂在 Step 4/5）

| 层级 | 内容 | 时机 |
|---|---|---|
| **S0 风格探索** | 定风格关键词 → **模型选型实验**（同 prompt 同 seed 横比）→ 沉淀 Style Block 三段 | **最先执行，未完成不出 L0** |
| **L0 四宫格基准卡** | 每个角色 1 张 2048×1024（2:1）：面部特写 + 正面全身 + 侧面全身 + 背面全身 | S0 之后，**角色资产第一步，强制** |
| **L1 表情集** | 从 L0 派生各表情/姿势立绘 | L0 确认后 |
| **L2 服饰变体** | 换装/季节/场景服饰 | 按需 |
| **S1/S2/S3** | 色卡提取 / 出图前预检 / 命名规范 | 贯穿 |

> **流程固定，风格不固定**：L0→L1→L2 的流程与题材无关；但**每个故事的美术风格不同 → 模型与提示词都不同**。
> 上一部的风格词绝不直接套新游戏，换风格必须重跑 S0。
> 无论选 A/B/C 哪种出图方案，**S0 → L0 都是角色资产的头两步**；出图方案在 Kickoff 确认。

## 4. 门槛与回退规则

| 门槛 | 位置 | 不过怎么办 |
|---|---|---|
| 客户确认锁定 | Step1 → 2 | 继续改稿 |
| P0 清零 / v0.3 冻结 | Step2 → 3 | 继续修订复审 |
| 分镜可审 / 指令可抄 | Step3 → 4 | 补分镜或修键位 |
| 四项沟通确认 | Step4 → 5 | 补确认 |
| **P0=0** | Step5 → 6 | 回 Step4 补资源 |
| **build Exit 0** | Step6 → 7 | 修编译错误 |
| **A–E P0=0、R1–R10 过** | Step7 → 8 | 回 Step6 修 |
| **DoD 7 条全满足** | Step8 → 完成 | 回对应 Step 补 |
