# Step 3 — 剧本化（分镜设计 + 剧本化）

> 本文件是 `avg-game-maker` 8 步流水线的 **Step 3** 模板。
>
> **Step 3 = 两个子阶段**：
> - **3a 分镜设计（Storyboard）**：把 Step 2 定稿的干净稿，按"镜头"拆成视觉规划（不写引擎指令）。
> - **3b 剧本化（Script-ify）**：把分镜表翻译成引擎指令数组（`script.ts` 的 `ScriptCommand[]`）。
>
> **通用化原则**：本文档的字段、键位、映射对所有题材通用。
> 引擎能力以 `src/engine/types.ts` + `renderer.ts` + `game-engine.ts` 实测为准（已在文中标注）。

---

## 0. 与上下游的关系

- **输入**：Step 2 定稿的 `v0.x_故事干净稿.md` + 设计骨架（角色体系 / 变量机制 / 结局设计）。
- **3a 产出**：`故事草稿/剧本化/分镜/<章节>_分镜.md`（每章一份分镜表）。
- **3a2 产出**：`故事草稿/剧本化/NN_分镜画面呈现审核_v1.md`（逐镜判定 + CG 候选清单）。
- **3b 产出**：`故事草稿/剧本化/<章节>_剧本化.md`（含可直接抄进 `script.ts` 的引擎指令）。
- **下游**：分镜表 / 剧本化里的资源引用，直接喂给 **Step 4 拆资源**（一镜 = 一组资源需求）。
- **门槛**：3a2 审核结论经用户拍板 + 3b 自检（§4）通过后，方可进 Step 4。

## 1. 流程

```
干净稿 v0.x
   │
   ▼  [3a] 分镜设计：逐段拆镜头，填分镜表（含景别/机位/构图/运动/转场/演出意图）
   │

   │

   │
   ▼  Step 4 拆资源（取分镜/剧本化里的 bg/sprites/anim/audio/item/cg 引用）
```

## 2. 3a 分镜设计 Storyboard

### 2.1 分镜字段表

**基础字段（沿用 Step 1 的 11 维度，作为每镜的基础信息）**
场景 / 时间（昼夜/时段）/ 人物 / 位置 / 动作 / 表情 / 对话 / BGM / SE / 特效 / 动画

**分镜专属视觉维度（新增）**

| 字段 | 取值示例 | 作用 |
|------|---------|------|
| **Shot#** | S01, S02… | 镜头序号，与剧本化段落对齐 |
| **景别** | 远景 / 全景 / 中景 / 近景 / 特写 | 决定立绘缩放 / zoom 强调 |
| **机位/角度** | 正面 / 侧面 / 俯视 / 仰视 / 过肩 | 决定是否需要非正面立绘（见 §2.2-③） |
| **构图** | 谁在左/中/右、占比 | 驱动 position 与同屏人数布局 |
| **镜头运动** | 固定 / 推 / 拉 / 摇 / KenBurns / zoom强调 | 映射到 effect(zoom) / 背景缓推 |
| **时长/节奏** | 秒数 或 "按文本" | 节奏参考（引擎按点击推进，时长仅作规划） |
| **转场** | →下镜用 fade/slide/iris/dissolve/flash/none | 映射到 scene.transition |
| **演出意图备注** | 为何这样拍、要什么感觉 | 给美术/编剧/自己的说明 |

### 2.2 四类特殊镜头（对应引擎约束，必须显式标注）

#### ① 多人同屏镜头（>3 人）
- **引擎已原生支持自动布局**：`game-engine.ts:318 drawAllCharacters` 在 N>3 或 position 冲突时，
  自动均匀分位 + 宽度收缩（`baseX=(i+1)/(N+1)`、`maxWRatio=0.9/(N+1)`），永不重叠。
- **分镜动作**：在"构图"列标注 **同屏人数 N**；剧本化正常 `char show` 多个角色即可，无需手动算坐标。
- **⚠️ 立绘大小一致性（硬约束）**：`drawCharacterAuto` 按图片**实际像素高度**缩放（高度占画布 75%）。
  若各角色立绘出图身高不一，缩放后大小会参差。**资源约定（Step 4 执行）：所有立绘统一出图身高基准**
  （建议 1000px 高，透明 PNG），保证同屏大小一致。

#### ② CG / 演出画面镜头（画面表现层）
- **何时用**：需要强表现力、不适合"立绘+背景"拼合的瞬间（回忆 / 梦境 / 抽象情感 / 关键 CG 插画）。
- **做法**：AI **一次性出全屏图**（非立绘+背景拼合），注册为独立的全屏画面资源。
- **剧本化映射**：`scene(cgKey)` 切到该全屏图 + 隐藏全部立绘（`char hide` 所有 id）。
  引擎 `renderBackground` 用 cover 全屏绘制，立绘是独立层，故隐藏角色即纯 CG 展示。
- **🔧 引擎预留接口建议**：当前用 background 通道 + 隐藏角色临时实现。
  建议未来给 `scene` 指令加 `kind?: 'bg' | 'cg'` 字段（或新增 `cg` 指令），
  使 CG 与常规背景在转场（iris/flash 更适合 CG）、缩略图、结局收集上有区别对待。
- ➡️ **"什么时候该出 CG"的判定规则与出图规范不在本小节**，见 **§2.4 画面呈现形式审核**。

#### ③ 非正面机位镜头（侧 / 俯 / 仰视）
- **分镜动作**："机位/角度"列标 侧面 / 俯视 / 仰视 / 过肩。
- **⚠️ 资源后果**：`position(left/center/right)` 只表示**屏幕站位**，不表示角色朝向/视角。
  非正面机位需要**对应角度的立绘图片**（侧身、俯视、仰视）。
- **→ Step 4 资源标注**：该镜需在资源总表里标"需 [角色] 侧身/俯视/仰视 pose"，
  在 G1 出图阶段（Step 4/5）补出对应角度立绘，与正面 pose 同键位区分（如 `alice_side`）。

#### ④ 动态表情镜头
- **现状**：换 `pose`/`expression` 当前是**硬切**（`drawAllCharacters` 直接 drawImage，无过渡）。
- **可行方案（二选一或组合）**：
  - **方案 A — anim 序列帧叠加（引擎已支持）**：把表情动作做成序列帧（眨眼 / 口型 / 脸红渐变），
    在立绘位置叠加播放：`anim play <id> <position>`（`animPlayer` 渲染在角色层之上，按 left/center/right 定位）。
    资源：表情序列帧（如 `alice_blink` 2–4 帧、`alice_blush` 渐变帧），登记进 `manifest.animations`。
  - **方案 B — 换表情淡入过渡（需引擎小改）**：建议给 `char` 指令加 `transition?: 'fade'` 选项，
    `drawAllCharacters` 检测 `expression` 变化后做 ~0.2s alpha 过渡，避免硬切跳变。
- **分镜动作**：在"演出意图备注"标"表情动态：眨眼/脸红/嘴动"，剧本化选 A 或 B 落地。

## 2.4 【3a2】画面呈现形式审核（必做闸门）

> **为什么必须单独审这一环**
> 分镜写到"人物·动作·表情"时，默认答案总是"背景 + 立绘"。但有三类镜头这个默认答案是错的：
> ① **立绘根本演不了**（蹲下放花、躺床抬手、背对、递接物件）；
> ② **没有角色可显示**（主角是玩家代入型、无立绘，独角戏只剩一张背景 + 旁白）；
> ③ **默认形式会稀释冲击力**（全剧高潮的定格、回忆闪回，站着念完就废了）。
>
> **实测教训（真实踩过）**：某部 20 章 / 117 镜的分镜里，「类型」列的 CG 标注是 **0 处**——
> 不是不需要，是**没有人审**。直到 Step 5 核对时才发现"整部戏一张 CG 都没有"，
> 而结局章大量"主角独角戏"镜头落地后就是**一张不动的背景 + 旁白**。
> 所以本环节是**闸门**：逐镜过，不许默认跳过、不许"看起来不需要"就整章略过。

### 2.4.1 判定：四档呈现形式

| 档 | 形式 | 用在 | 引擎落地 |
|---|---|---|---|
| **P1 背景 + 立绘** | 默认 | 有角色在台，情绪靠立绘的表情/姿态承载 | `scene(bg)` + `char show` |
| **P2 背景 + 立绘 + 特效/运镜** | 情绪升级 | 同一场景内要"再加一度"：`zoom` 强调 / `dim` 压暗 / `flash` 惊爆 / 天气 | 加 `effect` |
| **P3 物件弹窗 `item`** | 文书类证据 | **画面主体是一张纸 / 一个物件，且上面的字必须被读到** | `item <id>`（文字与印章 100% 由 PIL 画，见 `g2-item-art.md`） |
| **P4 CG 单图（全屏画面）** | 冲击力 / 立绘演不了 | 见 §2.4.2 的 6 条触发条件 | `char hide`×N + `scene(cgKey)` |

> **P3 优先于 P4**：只要画面主体是"可读的文书/物件"，一律先做 `item`——
> 更省、文字 100% 可控、同一物件可反复弹。
> CG 是给"**画面本身**（空间、姿态、光影、关系）才是戏眼"的镜头留的。
>
> **判定口诀**：这镜的戏眼是**"纸上的字"** → P3；是**"那一幕的样子"** → P4；两者都不是 → P1/P2。

### 2.4.2 CG 触发条件（命中任一 → 列入候选）

1. **立绘承载不了的躯干/四肢动作**：蹲、跪、躺、背对、拥抱、递接物件、抬手够物、手部特写。
   （立绘只有有限 poseKey，且全是"站立机位"；"蹲下身把白菊放在台阶上"用立绘画不出来）
2. **无人物但必须叙事的空镜**：挖开的地基里露出烧焦的书、深夜办公室只剩一盏灯。
   （没人物就没有 `char` 指令可发，纯背景 + 旁白 → 观众看到"一张不会说话的图"）
3. **主角无立绘的镜头**（玩家代入型主角）：主角的独角戏若全走背景，整章就没有画面主体。
4. **同屏 >3 且站位本身有叙事意义**：引擎会自动把 N 人排成一行、等宽收缩
   （`drawAllCharacters`），**构图被抹平**。要"围着病床站"这种关系构图，只能出图。
5. **跨时空 / 回忆 / 梦境 / 抽象**：画面质感不属于当前场景（老照片感、过曝、去色）。
6. **章节情感峰值**：该章最高潮的那一瞬，值得定格成一张图。

### 2.4.3 反向约束（防 CG 泛滥——同样重要）

CG 是最贵的资源（每张 = 一次完整构图出图 + 一次人工审），**不能因为"好看"就加**。逐条问：

- **能不能用 `item` 解决？**（主体是纸/物件 → 是，就做 item，别做 CG）
- **能不能用现有背景 + 立绘 + 特效演？**（换个 pose、加 zoom/dim/flash 就够 → 就够）
- **删掉这张 CG，观众具体损失什么？** 答不出具体一句话 → **不出**。
- **同一场戏最多 1 张 CG**（连出会让人物从"演出"变成"看画册"）。

### 2.4.4 审核产出物

一份 `剧本化/NN_分镜画面呈现审核_v1.md`，**逐章逐镜过**，至少含：

| 镜号 | bg | 默认形式 | 判定 | 理由 | 若 CG：画面内容 | 参考图（人物 / 场景） |
|---|---|---|---|---|---|---|

- **只列非 P1 的镜头 + CG 候选**（P1 占比最大且无需改动，不必逐条抄）。
- CG 候选每条必须写清**画面内容**：谁、在哪、什么姿态、什么光、什么时刻。
  空泛的"很有冲击力"不能作为依据。
- ⚠️ **必须交用户拍板**：画什么、要不要，属**审美与创作取舍**，与 `g2-item-art.md` §4.1
  （物件构图必须让用户选）是同一条原则。
  给用户的形态 = **候选清单 + 我的推荐子集 + 每张的参考图来源**，**不要自己定完就直接出图**。

### 2.4.5 P4 出图规范：**双参考图**（关键）

CG = "场景 + 人物"合一，所以**两张参考图缺一不可**：

| 参考图 | 取自 | 锁什么 | 不给会怎样 |
|---|---|---|---|
| **场景参考图** | 该场景的 `pano` 载一段（或已定稿的 16:9 引擎背景） | 空间结构、道具位置、光照方向、色调 | **场景漂移**：同一间咖啡馆，CG 与背景图看起来不像同一个地方 |
| **人物参考图** | 该角色 `default` **成品（已抠图 RGBA 贴白底）**裁出的「头 + 颈」 | 脸型、发型、肤色、年龄感 | **换脸**：CG 里的人不是那个角色 |

> 🔴 **裁切高度不能写死比例**（2026-09-16）：「顶部 20%」对头身比高的角色会**切在脸上**
> （实测肤色带底 25.7%~40.5%H）→ 参考图只剩头发、输出直接**丢脸**。
> 正解 = 按**实测肤色底**自动定高（钳 `[0.26, 0.34]H`）+ 用**已抠图 RGBA 贴白底**
> （`_gray` 底稿可能是绿幕，绿会被画进成品）。改了口径必须**改文件名版本号**，
> 否则云端按名命中会跳过上传。详见 `krea2-persona-sheet` §十一。

> ⚠️ **人物参考图必须是「头+颈」，绝不能用全身底稿**（2026-09-15 实测，代价 9 张废图）：
> 喂全身底稿时 Krea2 会进入「重画整件衣服」模式，按训练先验给角色**补出参考图里并不存在的服装元素**
> （实测：黑皮夹克 + 黑高领被补出**白衬衫领 + 白袖口的拉链立领**）。
> 提权到 `image1_tokens=max` 压不住；在**正向提示词里写「绝不出现白色衣领」更是无效甚至反效**
> （Krea2 的负向是 `ConditioningZeroOut` 零化通道，正向里写否定词等于在描述它）。
> 正解 = **参考图只给头颈，服装完全交给文字描述**。

#### 🔴 双参考图的「顺序 + 权重」是硬约束

`Krea2EncodeRebalance` 有两张参考图时（`image1` / `image2`），
**`image1` 被当作「画布底」，`image2` 被当作「内容源」**；
权重 `imageN_tokens`（`low`/`normal`/`high`/`max`）必须与顺序**成对**给。三组实测：

| 组 | `image1` / `image2` | `imageN_tokens` | 结果 |
|---|---|---|---|
| ❌ A | 【人物, 场景】 | 【high, *】 | 场景里画出一颗**巨大模糊人头**（人物参考图被当成画布底） |
| ❌ B | 【人物, 场景】 | 【low, high】 | **人物整个消失**，只剩纯场景 |
| ✅ C | 【**场景**, **人物**】 | 【**high**, **low**】 | 场景结构稳、人物按文字描述落位，无残留 |

> **口诀：谁「像画布」谁拿 `image1` + `high`。**
> 即 **场景 = 画布（锁结构 → `image1` + `high`），人物 = 身份锚（只取脸 → `image2` + `low`）**。
> 只改顺序不给权重、或只改权重不改顺序，都会落进 A / B 的坑。
- 构图要写清"这是**一张完整画面**（不是立绘海报）"：要有纵深与前后景，
  人物**不必居中**、可以只占画面一角。
- 尺寸出 **1920×1080**（与引擎背景同档），命名 `cg_<id>`，
  登记进 `manifest.backgrounds`（引擎当前复用 background 通道，见 §2.2-② 与 §6 的接口建议）。
- CG 出图同样受 **G1 一致性标准**约束（色调/影调须与全作一致），
  但它**不受"统一出图身高基准"约束**（那是立绘专用规则）。

**特例：玩家代入型主角（无立绘）的 CG 构图**

若主角是"玩家代入型"（**没有立绘**，只有 `speaker:"你"` 的对话），则：
- **CG 里主角默认不露脸** —— 用背影、手部、侧影、取景框外的第一视角。
- 原因有二：① **没有人物参考图可比对**，露脸必然脸崩/每次都不一样；
  ② 保持代入感（玩家看不到自己）。
- 主角独白镜头若全走背景 → 整章没有画面主体（实测：某作 125 镜里 32 镜是这种，
  三个结局章 15 镜中 13 镜无角色，落地后就是"一张不动的背景 + 旁白"）。
  **这本身就是 CG 触发条件 ③ 的最强形态。**

### 2.4.6 分镜表要回填的字段

审核完成后，把结论**回填进分镜表**（不要只留在审核文档里）：

- 分镜表的「类型」列：补 `CG` / `item` / `choice` 等标注（原本可能只有"普通/特写"）。
- 后段章的紧凑分镜表（只有 `bg|景别|机位|画面内容|人物(立绘)|…` 的那种）
  **若没有「类型」列，必须补一列**——否则 CG 判定无处落笔。
- 分镜表头部补一行：「呈现形式已审：YYYY-MM-DD（见 NN_分镜画面呈现审核_v1.md）」。

## 3. 3b 剧本化 Script-ify

### 3.1 键位总表（字段 → 引擎指令映射）

| 分镜维度 | 引擎指令 / 字段 | 取值与说明 |
|---------|---------------|-----------|
| 场景背景 | `scene.bg` | → `manifest.backgrounds` 的 key（全屏 cover 绘制） |
| 转场 | `scene.transition?` | `fade`/`slide-left`/`slide-right`/`none`/`iris`/`dissolve`/`flash` |
| 调色 | `scene.grade?` | `none`/`warm`/`cold`/`soft`/`dusk` |
| 天气 | `scene.weather?` | `none`/`petal`/`rain`/`snow`/`bokeh` |
| 人物出现 | `char show` | `id`, `position`:`left(0.2)/center(0.5)/right(0.8)`, `pose`, `expression?` |
| 人物退场 | `char hide` | `id` |
| 人物换姿/换表情 | `char move` | `id`, `position?`, `pose?`, `expression?`（当前硬切，见 §2.2-④） |
| 同屏多人 | 多个 `char show` | 引擎自动布局（N>3 自动缩放并排，见 §2.2-①） |
| 对话 | `dialog` | `speaker`, `text`, `expression?`（说话人表情） |
| 旁白 | `narration` | `text` |
| BGM | `bgm` | `action`:`play`/`stop`/`fadeout`, `id?`, `duration?` |
| 音效 | `se` | `id` |
| 特效 | `effect` | `shake`/`flash`/`dim`/`rain`/`snow`/`petal`/`bokeh`/`zoom`, `duration?` |
| 序列帧动画 | `anim` | `action`:`play`/`stop`, `id`, `target?`, `position?`（可叠加表情层） |
| 等待 | `wait` | `duration`（秒） |
| 分支选择 | `choice` | `choices:[{text,label,condition?}]` |
| 变量修改 | `set` | `variable`, `value`, `op`:`=`/`+=`/`-=`（**无 add**） |
| 条件跳转 | `if` | `condition`, `trueLabel`, `falseLabel` |
| 跳转 | `jump` | `label` |
| 标签 | `label` | `id` |
| 结局解锁 | `unlock` | `ending`（→ `StoryDef.endings` 声明，按 storyId 持久化） |
| CG 画面 | `scene`(cgKey) + `char hide`×N | 见 §2.2-② |
| 结束 | `end` | 终局 |

> 完整 `ScriptCommand` 联合类型定义见 `src/engine/types.ts:27`。

### 3.2 四类镜头 → 指令映射（速查）

| 分镜类型 | 剧本化写法 |
|---------|-----------|
| 普通镜头 | `scene` → `char show` → `dialog`/`narration` → … |
| CG 镜头 | `char hide`(全部) → `scene(cgKey, {transition:'iris'})` |
| 多人(N)镜头 | 多个 `char show`（position 可重复 left/center/right，引擎自动均匀分） |
| 非正面机位 | `char show(id, {pose:'side'})` —— pose 用对应角度立绘 key |
| 动态表情 | `anim play('<id>', '<position>')`（叠加）或 `char move` + `transition:'fade'`（方案 B 需引擎支持） |

## 4. 自检清单（3b 完成后逐条过）

- [ ] **键位合法**：所有 `bg`/`id`/`pose`/`expression`/`ending` 均在 `manifest` 或 `StoryDef` 中已声明（未登记会 404 崩溃）。
- [ ] **分支闭合**：每个 `choice` 的 `label` 都有对应 `label` 定义；所有分支最终汇回主线或 `unlock` 结局。
- [ ] **变量自洽**：`set` 的 `op` 仅 `= / += / -=`；`if` 条件引用的变量已被 `set` 初始化。
- [ ] **CG 镜头**：CG 类已 `scene(cgKey)` + 隐藏全部立绘；`cgKey` 已在 `manifest.backgrounds` 登记。
- [ ] **多人镜头**：同屏 N 人已确认立绘出图**统一身高基准**（§2.2-①）。
- [ ] **非正面机位**：已标注需侧/俯/仰视立绘，并在资源表挂接对应 pose key（§2.2-③）。
- [ ] **动态表情**：已选定方案 A（anim 叠加）或 B（淡入），资源/接口就绪（§2.2-④）。
- [ ] **音频预留**：BGM/SE 仅登记实际存在的文件（缺失不登记，否则 `loadAudio` 404 崩溃）。

## 5. 与 Step 4 的衔接

分镜表 / 剧本化是 **Step 4 拆资源的直接输入**。提取规则：

- **背景**：所有 `scene.bg` 值（含 CG 的 `cgKey`）→ 背景资源需求。
- **CG**：审核（§2.4）判为 P4 的镜头 → **独立出图需求**（每张需人物参考图 + 场景参考图），
  与普通背景分开登记（普通背景可复用，CG 是一次性画面）。
- **立绘**：所有 `char show/move` 的 `id`+`pose`/`expression` 组合 → 立绘资源需求（含非正面角度 pose）。
  ⚠️ **必须逐镜扫「动作/表情」列与「机位」列**，不能只登记出现过的 `pose` 键——
  分镜里常写"蹲放""擦杯""手指收紧""侧脸"这类**动作/神态描述**，它们都需要各自的 poseKey，
  漏扫就会出现"分镜写了、资源表没有、脚本里取不到图"的静默缺图（见 `step4-resource-planning.md` §4.3b）。
- **物件**：审核判为 P3 的镜头 → `item` 资源需求（走 `g2-item-art.md` 产线）。
- **动画**：所有 `anim` 的 `id` → 序列帧资源需求（含动态表情帧）。
- **音频**：所有 `bgm`/`se` 的 `id` → 音频资源需求（仅实际登记的）。
- **特效/天气**：`effect`/`weather` 值 → 引擎内置，无需出图，仅确认引擎支持。

> Step 4 据此合并去重，产出资源总表；G1（角色一致性）在出图阶段按本步标注的 pose 角度补齐角色资产。

## 6. 引擎预留 / 扩展建议（供未来迭代）

| 项 | 现状 | 建议 |
|----|------|------|
| CG 接口 | 复用 background 通道 + 隐藏角色 | `scene` 加 `kind:'cg'` 或新增 `cg` 指令，区分转场/缩略图/结局收集 |
| 动态表情（换表情过渡） | 硬切 | `char` 指令加 `transition:'fade'`，`drawAllCharacters` 检测 expression 变化做淡入 |
| 非正面立绘 | 需手动准备侧/俯/仰 pose | 出图阶段（G1）按分镜机位批量生成角度变体 |
| 立绘身高基准 | 依赖出图统一 | 在资源规范里**强制**统一出图高度（如 1000px），避免缩放参差 |
