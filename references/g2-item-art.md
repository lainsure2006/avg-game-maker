# G2 — 物件/物证图（`item` 弹窗用图）：AI 质感底图 + 程序排版

> 适用：信件、报纸、报告、表格、借书卡、便签、账本、印章、邮戳……一切**「上面有字」的平
> 面道具**。挂在 Step 4/5，是「图片出图工作流」里与 G1（角色）并列的第二条产线。
>
> 核心结论（血的教训，先记住这句）：
> **文生图模型永远画不对中文小字。凡是剧情要读的文字，一律不交给 AI，全部用 PIL 叠。**

---

## 1. 为什么不直接让 AI 画带字的道具

实测（Krea2 / Flux 系，中文编码器为 Qwen3-VL）：

| 现象 | 结果 |
|---|---|
| 「报纸内页 + 正文」 | 正文被画成**明显乱码笔画**，缩小也看得出 |
| 「卡上有红色印章」 | 章内文字必是**乱码**（AI 无法生成可读的章面汉字） |
| 「页边有几行蓝色手写批注」 | 画出**半可读的错字**，比乱码更糟（玩家会误读） |
| 「纸面完全空白，没有任何印章、没有任何文字」 | ⚠️ **反而画出乱码红章** —— 正向提示里出现「印章/红字/手写」就是在给它采样权重 |

剧情靠这些字推进时（物证/信件的「戏眼」），错一个字剧情就断，且 `item` 弹窗会强制玩家细看。
所以文字必须 100% 可控。

### 铁律
1. **底图只出「材质与光影」**：纸张纤维、折痕、焦边、污渍、台灯冷光、桌面反光。
2. **提示里绝不提**「印章 / 红章 / 红色印记 / 手写批注 / 文字」——连否定式也不能提。
   只说「纸面素净空白」。（提「没有任何印章」＝照样画出来）
3. 印章、邮戳、红圈、箭头、签字、正文——**全部 PIL 画**。
4. 底图出完**必须开图看**：文件体积 5–6KB = 单色空图（history 会谎报 success）。

## 2. 两条产线：纯叠字 vs 混合排版

| | A. 纯叠字 | B. 混合排版 |
|---|---|---|
| 适用 | 底图的**版面结构已经对**（表格线、横格线、空白横幅都在位） | 底图结构不可控（报纸正文、多栏公文） |
| 做法 | AI 出整张带结构底图 → PIL 只在预留位置叠字 | AI 只出**素材**（纸张纹理、照片）→ 版面由 PIL 从零排 |
| 例 | 第七封匿名信、借书卡、值班表、赊账本 | 火灾报道报纸（Krea2 连出两版都跑偏：先是满版乱码，后是一整张现场照片） |

**判断标准**：如果重出 2 次结构仍不对（模型把「报纸」理解成「照片」），别第三次死磕，
直接切 B —— 报纸/公文本质就是排版，PIL 排出来比 AI 更像真的，而且一个错字都没有。
`paper_tex()` 可以从底图里裁一块纯纸面区域平铺成整幅纸张纹理，物尽其用。

## 4. 排版必踩的坑

### 4.1 ★ 纸面几何：倾斜（rotation）与透视（perspective）是两件事

底图是「斜拍桌面上的纸」，纸在画面里同时带**倾斜**和**透视**。文字层按画面绝对像素排，
所以天然对不上。先分清两者，否则会一直用旋转去救一个旋转救不了的问题：

| | 表现 | 整层旋转能救吗 |
|---|---|---|
| **倾斜** | 纸整体歪了，上下边**等长且平行** | ✅ 能（绕图心转同角度） |
| **透视** | 近大远小，上下边**不等长**（梯形） | ❌ **不能** — 无论转多少度，文字都不可能同时贴住上下两条边 |

实测 15 张底图（左低右高为正）：

| 档 | 物证 | 倾斜 | 透视（上/下宽比） |
|---|---|---|---|
| 强 | `postmark` 信封 | +19.7° | 1.28 |
| 强 | `seven_papers` 七张纸 | −16.3° | 各张角度还互不相同 |
| 强 | `letter7` 方格信纸 | −15.5° | 1.16 |
| 强 | `report_copy` 复印件 | +14.4° | 0.92 |
| 中 | `fire_report_table` 消防表 | −11.4° | 梯形 4.8° |
| 中 | `report_p18` 第十八页 | +11.3° | 1.11 |
| 中 | `note_lu` 便签 | −10.9° | 0.71 |
| 轻 | `two_timelines` 值班表 | +1.7° | — |
| 轻 | `regular_list` 账本 | +0.4° | — |

**只有「轻」档能直接按正坐标排版**（步长为零，看不出错位）。中/强档必须在下面三条路线里选
—— 但**先看下面这节**，它是不可逆的。

#### ⚠️ 先停一下：这是审美取舍，出底图之前必须让用户选

改构图 = 给**整个道具系列定观感**，且不可逆（改了就得重出全部底图 + 全部重排）。
所以**必须在出底图之前问，不能出完再问**。

我上一轮的教训：按功能推「证物是给人看字的 → 正拍更清晰 → 所以更好」，自作主张定了路线 A，
还替用户否决了斜拍。用户看完实测对比的判断相反 —— **斜拍版「更有感觉、更真实」**，
即使字没完全落在格线上。

> 🔑 **证物的戏眼是「这像一件真的旧物」，不是「这行字看得清」。**
> 清晰度、对齐度都还能靠排版优化补回来；质感一旦丢了，补不回来。
> **别用工程指标替用户做审美决策。**

**现成的选择题素材**（下次直接 `present_files` 给用户，**不用重出试产图**）：

| 文件 | 内容 |
|---|---|
| `fogport_assets/item_bases/_对比_斜拍vs正拍_letter7.png` | 同一文案在两种底图上的落位对比（上下并排，带标题栏） |
| `fogport_assets/item_bases/Krea2_Item_letter7_flat.png` | 正拍版底图样张 |

生成：`python demo_flat.py`

问法示例：

> 道具图有两种构图，你选哪种？（这决定了全部道具的观感，后期要改得重出重排）
> **A 斜拍** —— 像桌上随手拍到的旧物，有氛围、更真实；代价：纸面只占约 1/4，
> 　　　　　　字偏小，且要逐张量倾角旋转贴合
> **B 正拍** —— 纸撑满画面，字大清晰（纸面像素 **×3.9**）；代价：更像"扫描件"，少了现场感
>
> 📌 参考：上一部《雾港回声》你选了 A，理由是"更有感觉、更真实"。

---

#### 路线 A：重出「正拍撑满画面」（清晰度优先）

根因在提示词：一旦写「俯拍特写 + 桌面环境 + 浅景深」，纸就注定**又小又斜**。改成
**垂直俯视 + 纸边平行画面 + 撑满画面**即可，**已实测验证有效**：

| | 旧（俯拍特写） | 新（垂直俯拍撑满） |
|---|---|---|
| 纸面占画面 | **24.5%** | **95.0%** |
| 格线倾斜 | −15.5°，需旋转校正 | ≈0°，无需校正 |
| 纸面像素量 | 基准 | **×3.9**（字迹清晰度同比例提升） |

提示词配方：

```
✅ 垂直俯视正拍，纸面与画面平行、四边与画面边缘平行，
   纸张撑满整个画面，四周只留极窄的桌面边缘，无明显透视
❌ 俯拍特写 / 桌面环境 / 浅景深 / 斜拍
```

收益是双份的：**几何变正**（排版退回普通正坐标，`paste_rot(angle=0)`）+ **清晰度 ×3.9**。
代价是重出该批底图（约 2 分钟/张）+ **丢掉氛围感**。

#### 路线 B：保留斜拍 + 整层旋转贴合（质感优先）★ 本次采用

不动底图，只把文字层绕图心旋转到与格线同角度。**成本最低，用户审美上更认可**。

```python
# 量倾角：在两条 x 窗口里找横线的 y，比较差值拟合斜率
angle = math.degrees(math.atan(slope))
im = paste_rot(im, ly, angle=angle, center=(W / 2, H / 2))
```

实测角度：`card_burnt` −9.3°、`report_copy` −3.79°、`fire_report_table` +2.0°、`letter7` +1.3°、`note_lu` −3.0°。
对**透视强**的纸面旋转只能做到"近似"（救不了梯形），但**用户宁可要这个近似，也不要失去质感**。

**结论：够用就不要升级。** 「字没精确落在格线上」在成品里几乎看不出来，
而「像扫描件」一眼就看出来。

#### 路线 C：单应变换（透视贴图）— 既要质感又要精确对齐时才用

**只在「用户既想要斜拍质感、又要求字精确贴住格线」时才值得上**（例如报纸、表格这类
格线本身是视觉主体的道具）。路线 B 能过的就别升级到 C ——
C 要逐张人工校准四角，成本高得多，而用户往往感受不到那点提升。

`persp.py` 已实现完整单向映射：**在「摊平的正置纸面」坐标上正常排版**，再用 3×3 单应矩阵
把整层拍到底图的斜纸上，倾斜与透视一次解决。

```python
import persp as P
quad = P.solve_quad("letter7")        # 自动求纸面四角（可覆盖为人工四角）
im   = P.paste_quad(im, ly, quad)     # 文字层按 quad 透视贴图（内部 2× 超采样）
# 预览：python persp.py  → _透视框预览.png（15 张框线联络表，用前必看）
```

⚠️ **自动求 quad 不可靠**：实测有角点算到画面外（`regular_list` 只框到右半、
`two_timelines` 角点在画面外）。用之前**必须**先看 `_透视框预览.png` 逐张确认，
不准的在 `CLIPS[iid]` 里传人工四角 `[TL, TR, BR, BL]`。

纯 PIL 自实现（本环境 **numpy / scipy / cv2 全都没有**，`Image.MESH` 是反向语义、
不能做「源 box → 目标 quad」正向映射，所以只能手写单应 + 逐像素采样）。

**选路判据（顺序即优先级）**：

1. **先问用户**（§4.1 开头那节）—— 这是审美决策，不由流程决定。
2. 用户选**质感** → **路线 B**（默认值，本次《雾港回声》采用）。
3. 用户选**清晰** → **路线 A**（重出底图，几何与清晰度一次解决）。
4. 用户**既要又要**，且道具的格线本身是视觉主体（报纸/表格）→ **路线 C**。
5. 一张图**别混用**两种构图 —— 15 张道具是一个系列，观感必须统一。

### 4.2 带字距的文本会忽略对齐锚点 ★
逐字绘制实现字距时，`anchor` 的水平分量会被当成起点 → 右对齐/居中的文字整体跑偏
（实测报头日期被画出画面外）。必须先量总宽再回退起点：

```python
total = sum(f.getlength(c) for c in s) + spacing * (len(s) - 1)
if h == "m": x -= total / 2
elif h == "r": x -= total
```

### 4.3 「✓」不要用字体画
`simkai` / `simhei` 里**没有 U+2713 字形** → 渲染成空白，静默丢失。
勾号用两段折线画（`tick()`）。

### 4.4 红圈别圈太大
「徒手红圈」的框要**贴着字宽**，不要按栏宽取。
一个 480px 宽的椭圆圈 150px 的文字，看起来就是画错。

### 4.5 底图自带的「预留位」要盖准
出底图时若要求了「预留一块空白圆区供盖邮戳」，那么叠章时必须**盖在这块圆区正中**，
否则圆区会露在章外，像一块脏印。量出圆区圆心/半径再定章的位置与大小。

## 5. 客观校验：差分法（别靠肉眼）

**教训**：在缩略图上目测坐标误差可达 **100px 以上**（多次看偏），完全不可靠。
正解是把成品减去底图，差值即「我叠上去的墨迹」，再量包围框：

```python
d = ImageChops.difference(base, out)          # 底图 vs 成品
# 逐行扫 >thr 的像素 → 合并成「行带」→ 每带的 (y0,y1,x0,x1)
```

`verify_items.py` 会打印每张的纸面范围 + 每处墨迹包围框，越界自动标 ⚠️。
这样才能确认：文字在纸内、在栏内、在格内。

## 6. 出图侧的两个坑（会浪费大量时间）

### 6.1 「提交成功却 8 秒跑完、文件字节数与上次一模一样」
`find_output()` 若**只按 SaveImage 文件名前缀**在 `/history` 里找产物，
会命中**上一轮同前缀的旧产物** → 静默拿回旧图，看起来像「重出没生效」。
**必须传 `pid`**，只在本次任务里找。顺带好处：能提前读到 `execution_error`
（如 `[Errno 122] Disk quota exceeded`）立即失败，不再空等 600 秒。

### 6.2 重出时旧图要留档
用 `os.replace(dst, dst[:-4] + "_old%02d.png" % seed)` 改名留档，**不要删**
（本环境 safe-delete 会拦截并级联删除）。
