# Krea2 人物资产参考图（角色设定表）

**核心结论**：出「单图多视图排版」必须用 **Krea2**（Flux 系：DiT + Qwen3-VL 中文编码器）。
**SDXL（Juggernaut / Illustrious / Anything 等）做不了这件事** —— 会构图错位、人物融合、糊。不要再用 SDXL 试。

## 何时用
- 要一张角色设定表：左侧三个全身视图（正 / 90°纯侧 / 背）+ 右侧面部特写。
- 要为后续分镜立绘/多机位图提供「人物一致性锚点」。

## 一、必备模型（云端需齐备；缺一即失败）
| 用途 | class_type | 文件名 |
|---|---|---|
| 主模型 | `UNETLoader` | `krea2_turbo_int8_convrot.safetensors`（weight_dtype=`default`）|
| 文本编码器 | `CLIPLoader` | `qwen3vl_4b_fp8_scaled.safetensors`（type=`krea2`, device=`cpu`）|
| VAE | `VAELoader` | `qwen_image_vae.safetensors` |
| 二次元 LoRA（可选）| `LoraLoader` | `krea2/krea2_retroanime.safetensors`（strength 1.0；不够味可 1.3）|

> 其他可用 LoRA：`krea2_darkbrush / krea2_rainywindow / krea2_sunsetblur / krea2_neondrip / krea2_softwatercolor / krea2_dotmatrix / krea2_vintagetarot`（可用于氛围/风格微调）。

## 三、参数（照抄，别乱调）
- `EmptyLatentImage`: **1536 × 768**（横长条 2:1）。别用 SDXL 式大尺寸。
- `KSampler`: **steps=8, cfg=1.0（固定）, euler, simple, denoise=1.0**。
- 负提示：**必须用 `ConditioningZeroOut`（挂在空 CLIPTextEncode 上），绝不能写负面词** —— Krea2 turbo 不吃负面词，写了反而出怪。
- cfg 调高必崩；步数别加。

## 四、中文提示词模板（Qwen 编码器中文遵循度最强，务必用中文）
```
{排版前缀}{风格}{角色外观}{收尾}
```
- **排版前缀（固定，勿改版式措辞）**：
  `角色设定参考图，一张图内包含该角色的多个视图：左侧为三个全身视图并排（从左至右：正面、90度纯侧面、背面），右侧为一张面部特写。`
- **风格**（二选一）：
  - 真人：`真人照片质感，写实摄影风格，高清摄影。`
  - 二次元：`二次元动漫插画风格，日系动画，赛璐璐上色，2D illustration。`
- **角色外观**：`{年龄}{种族/国籍}{性别}，{发色}{发型}，{瞳色}{眼型}，{面部特征}，{肤色}，{身材}。身穿{服装}。`
- **收尾（必加，防缺陷）**：
  `纯白背景，均匀影棚光线，无阴影，无文字，无 logo，高清，细节清晰，完整身体，双脚着地。`

## 六、已知坑（必读）
| 现象 | 原因 | 处理 |
|---|---|---|
| 侧面变 3/4 | 写了「3/4 侧」 | 必须写「**90度纯侧面**」；可加「严格侧面，只能看到一只眼睛一只耳朵」 |
| 图上出现假文字/logo | 参考表易触发字幕 | 收尾加「无文字，无 logo」 |
| 脚被裁 / 人物浮空 | 全身图常见 | 收尾加「完整身体，双脚着地」 |
| 出怪 / 负面词无效 | 写了负面提示词 | 改 `ConditioningZeroOut`，**不写负面词** |
| 变糊/变差 | cfg 调高 或 尺寸超域 | 保持 `cfg=1.0`、`1536×768` |
| **轮询卡死/取到别人图** | CloudStudio 实例常被**共享**，别人也用 `TMP` 等通用前缀，编号撞车 | **SaveImage prefix 用唯一串**（如 `FP_<角色>_<风格>`）；轮询用**全量 /history 按前缀匹配**，不要靠 prompt_id 硬等单条 `/history/{pid}`（该部署单条接口可能返空） |
| 拉不下来 | 共享实例拥堵 | 全量 /history 里按前缀捞，再 /view 直下 |
| **下载到错图/旧图（尺寸与预期不符）** | 共享实例 `TMP` 等通用前缀编号撞车，轮询捞到历史同名产物 | **下载后必须用 PIL 校验真实尺寸**（`Image.open(p).size`），确认是 1536×768 而非历史撞车文件；靠唯一前缀 + 全量 history 前缀匹配可根治 |
| **重出同一角色却拿到上一次的旧图** | `prefix = FP_<角色>_<风格>` 是**固定串**，重跑时 `find_output` 若**只按前缀**匹配会命中历史里那条旧产物（`/history` 全量仍在），新图反而被跳过 | **根治：取图必须传 `pid`**，只在本次任务内匹配（已修入 `comfy_krea2_sheet.py`）。表现为「8 秒就跑完、落盘字节数与旧图**一模一样**」的静默失败。旧 workaround（传 `prefix_extra` 换前缀）仍可用但已不必要 |
| **「提交成功却抓不到产物」空等 600 秒** | 任务真的失败了，但只轮询产物的话看不到原因 | 传 `pid` 后可在同一轮询里读到 `status.messages` 的 `execution_error`，**立刻失败并报出 `node_id` + `exception_message`**（如 `[Errno 122] Disk quota exceeded` 直指云端配额满），不再空等 |
| **样貌偏离设定年龄**（如 35 岁出成 45–50） | desc 里的「**灰色鬓角 / 花白 / 沧桑**」等词会被模型放大成大量灰发+皱纹 | 要出年轻角色就写「**看起来三十出头，皮肤紧致光滑，额头与眼周没有明显皱纹**」，灰发只写「仅鬓角微见霜色」；反之要老就明确写皱纹/沟壑 |
| 人物气质不对（如「书卷气」出成落魄脏旧） | desc 只给抽象气质词、没给**具象道具/整洁度** | 抽象气质要靠**具象锚点**落地：「书卷气」→ 配一副旧式金属细框眼镜 + 衣着干净整洁 + 书房/旧书摊主身份；再与已出角色撞脸时，用眼镜/发型/整洁度做**区分度** |
| **角色不够好看/当不了「颜值担当」** | desc 只写年龄+服装，没给审美向锚点 | 在 desc 里直写**具象明星感锚点**：女性「五官精致立体、轮廓清丽、冷白高级、极其上镜」；男性「五官清秀干净、温润如玉、清俊耐看」；再加「极具镜头感与主角光环」。**但务必同时保留人设关键词**（如刑警的"克制冷静、气场硬朗"、店主的"文艺安静、内敛"），否则会跑偏成柔弱/油滑 |
| 首次很慢 | Qwen 编码器在 CPU 上，模型加载久 | 正常，首张可能 1–3 分钟；后续快 |
| **批量跑几张后突然全部失败** | **云端磁盘配额满**：`SaveImage` 报 `[Errno 122] Disk quota exceeded`。注意**采样节点全部 `execution_cached` 命中了**——图其实已生成，只差最后写盘，所以「提交成功却永远没产物」 | 让用户在实例终端执行 `rm -rf /workspace/ComfyUI/output/* /workspace/ComfyUI/temp/*`，**`input/` 千万别删**（里面存着复用中的参考图，正是靠它绕过上传 500）。清完必须重跑；一张 1280×960 约 1MB，几十张就会撑满 |
| **`/upload/image` 阶段性整体 500** | 云端上传端点抖动，与磁盘满无关 | 脚本带 4 次重试；仍失败时**先探 `GET /view?filename=<ref>&type=input`**，若参考图已在 `input/` 里就直接引用，跳过上传（已验证可行） |

## 八、端到端执行流程（已验证 · 雾港回声陆昭实战）
1. **索取当前 endpoint**：CloudStudio 实例每次重启地址都变，旧的会 403/过期 → 出图前必须向用户要最新 URL。
2. **探活 + 核对模型**：`OP.open(URL+"/system_stats")` 确认活着；`/object_info/UNETLoader` 看 `required.unet_name[0]` 含 `krea2_turbo_int8_convrot`，同理核对 CLIP/VAE 文件名在列。
3. **锁定角色设定**：出图前与用户确认性别/外貌/服装——曾因「设计文档写女性 vs 口头说男性」冲突导致返工。
4. **写 runner**（中文 desc 内联，不走 CLI）→ 调 `gen_one(op, base, name, desc, style, outdir, seed)`，`style` 可 `"both"` 一次出真+二次元两张。
5. **后台跑**：Qwen 编码器 CPU 加载慢，首张约 1–3 分钟；共享实例可能被他人排队挤慢。
6. **下载后 PIL 校验尺寸**：`Image.open(p).size` 须为 `(1536, 768)`，否则是撞车错图，**改名留档后重跑**（`_old%02d` 后缀；别用 `rm`，本环境 safe-delete 会拦截并级联删除）。
7. **交付**：`present_files` 给用户审四视图（左三全身正/90°侧/背 + 右面部）是否同一人、全身完整无裁切。
8. **重出/整改某张**：直接覆盖同名文件即可——取图已按 **`pid`** 精确匹配，不会捞回旧图（`--force` / 覆盖）。desc 按上表「样貌偏离 / 气质不对 / 颜值担当」三条针对性改写。
9. **批量出图前先确认云端有余量**：见 §六「批量跑几张后突然全部失败」——配额满是批量的头号杀手，**一张 1280×960 约 1MB**，几十张就撑满。

## 九、分辨率铁律（重要）
- **Krea2 原生工作分辨率就是 1536×768**（fp8/int8 turbo 蒸馏，低分辨率是设计如此）。
- **不要为了「更清晰」提高分辨率**（如改 2048×1024 / 3072×1536）——会偏离模型训练域、排版反而崩、画质降。

## 十、从角色表出「游戏立绘」（参考图形式 = `Krea2EncodeRebalance`，2026-09-15 三组实测更正）

> 需求：游戏要的是**单人**半身立绘，不是四视图表。要用角色表当**参考图**锁身份再出单人图。
> ⚠️ **Krea2 无 IP-Adapter**；Krea2 原生「参考图」节点是 **`Krea2EncodeRebalance`**（text + clip + image1..4 → CONDITIONING）。
> 🔴 **本节曾在 v1.2.0 写错**（声称"`Krea2EditRebalance` 出白图 → 改用 img2img"），是错判，已更正。img2img 会重绘面部导致"脸变、气质变、只保住服装"（用户实拍否决）。

### 节点选型实测结论（同一套已验证 KSampler 链，只换正向 conditioning 来源）
| 方案 | 结果 |
|---|---|
| **`Krea2EncodeRebalance`（text+clip+image1..4）** | ✅ **正解**。身份/发型/五官/服装全锁住，构图按提示词走。稳定出 1MB 真图。 |
| `Krea2EditRebalance` | ❌ 配 `krea2_turbo` **出黑图**（~5.8KB 纯黑，history 却报 success）。**不要用**。 |
| img2img（VAEEncode + denoise≈0.5） | ⚠️ 能出图但**高频面部被重绘**——脸/气质变、只保住服装色块。仅作兜底。 |
| `Krea2StyleReferenceNode` | ⚠️ 输出 `KREA_STYLE_REF`，只被云端 API 的 `Krea2ImageNode`（需 auth）消费，不接本地 UNET。不用。 |
| IP-Adapter 系 | ❌ 与 Krea2/Flux 权重不匹配，用户明确排除。 |

### 关键认知（都是实测踩出来的）
- **必须 `CLIPLoader(..., device="cpu")`** —— 与用户验证过的成功配置 `krea2_charsheet_real.json` 一致。
- 采样链沿用**用户验证过的 txt2img 链**即可：`CLIPTextEncode("")→ConditioningZeroOut` 当负向，`KSampler(cfg=1.0, steps=8, euler, simple, denoise=1.0)`。**不要自创 `BasicGuider+SamplerCustomAdvanced` 链**（那是 `krea2_wf.json` 编辑流，配 turbo 会退化）。
- **参考图数量决定版式**：喂 2 张（正面+脸）→ 出**双格**排版；喂 **1 张** → 出**单幅**。要单幅立绘就只给 `image1`。
- 画幅：**竖 768×1536** 出半身/全身立绘（推荐）；横 1536×768 会被裁成头肩。
- **"黑图/白图"假成功**：PNG 只有 5–6KB 就是单色空图——**必须开图 + 看体积**才能识破（history 会谎报 success）。

### 节点图（`Krea2EncodeRebalance` = 参考图锁身份出单幅立绘）
```
UNETLoader(krea2_turbo_int8_convrot)                        -> model
CLIPLoader(qwen3vl_4b_fp8_scaled, type=krea2, device=cpu)   -> clip
VAELoader(qwen_image_vae)                                   -> vae
LoadImage(参考图: 面部特写)                                   -> IMAGE
Krea2EncodeRebalance(text, clip, image1=LoadImage,
                     image1_tokens=high)                    -> positive  # ← 核心，替代 CLIPTextEncode
CLIPTextEncode("") -> ConditioningZeroOut                   -> negative
EmptyLatentImage(768, 1536)                                 -> LATENT
KSampler(model, positive, negative, latent, seed, steps=8,
         cfg=1.0, euler, simple, denoise=1.0)                # 用户验证过的链
VAEDecode -> SaveImage
```

### 参考图怎么切（从四视图长条）
```python
# 按「白底间隙」切列：逐列 getextrema()[0] < 245 判有内容，连续 >40px 为一段
# 最左段 = 正面全身；最右段 = 面部特写（段数不足时取右侧 ~24% 区域）
# 半身立绘首选参考 = 面部特写（头肩，约 369×768）→ 单张喂 image1
# ⚠️ 非正面机位（side / 背身）：改用【同一张表里的侧面列】裁头部当参考，见下
```
> 🔴 **出非正面机位立绘（`side` / 背身）—— 参考图必须与目标机位「同源」（2026-09-15 实测新增）**
>
> 要出 90° 侧身，就取角色表里的**侧面列**裁到只剩头部当 `image1`，**不要用正面的面部特写**：
> - 用正面参考 + 提示词写「纯侧脸」→ 模型得自己**推断**侧面轮廓，容易出「正脸歪头」「四分之三侧脸」，一致性差。
> - 侧面列裁头部：**bottom ≈ 0.155H**（实测侧身列 132×768，裁到 0.155H 正好只含头、不露衬衫领；**发量高的角色固定 0.155H 只切到头顶/无脸，通用脚本 `gen_side.py` 会 auto 加深到含脸为止，如江砚 0.220H**）
>   → **放大 4 倍贴白底**（参考图太小模型抓不住细节）→ 一次即中：纯 90° 侧脸，服装完全由提示词决定。
> - **切列实测（陆昭 1536×768 表）：只切出 3 段** —— `segs[0]`=正面全身、`segs[1]`=90° 侧身（宽仅 132，侧身天然窄）、
>   `segs[2]`=背面+面部特写（宽 921，两视图间白隙不够被并成一段）。
>   **别假设一定是 4 段** —— 切完存成段图逐张目视确认（`probe_luzhao_side.py` 可复用）。

### 出「游戏立绘」的构图 / 透明背景 / 换装（2026-09-15 实战，雾港回声陆昭）
- **构图别裁**：按「从头到腰部完整入镜」提示词，Krea2 在 768×1536 下实际给的是**头顶到大腿的 3/4 身**。**不要再 PIL 裁切**（裁 58% 会变成头到胸，太紧，用户否决）。直接用原图当立绘。
- **换装**：参考图只用**面部特写（`image1`）**，服装完全交给提示词。若拿带旧服装的「正面全身」当参考，**旧衣服会传染**到新图。
  提示词骨架：「保持参考图中人物的脸型、五官、发型、肤色、气质完全不变，只改变服装。」+ 新服装描述。
- **参考图必须裁成「纯头部」——否则旧服装会从参考图里传染过来（本 skill 最大的坑）** ⚠️
  面部特写段的底部常常露出**肩部/衬衫领**（实测陆昭的参考图右下角就带着白衬衫领）。
  Krea2 会把参考图的**服装信息一起编码**，生成时"接续"参考图的衣服 —— 表现就是
  **无论提示词怎么写「黑色高领/没有白衬衫」，都顽固长出白衬衫领和白袖口**（实测 6 张全部中招，
  堆叠再多否定词也压不住）。**修复 = 把参考图纵向裁到只剩头部**（`im.crop((x0,0,x1,int(H*0.80)))`），
  服装才完全由提示词控制。裁完立即生效：白衬衫/白袖口彻底消失。
  > 教训：遇到"模型总加某个元素"，先怀疑**参考图**在暗示它，再改提示词——改文字是无效功。
- **一次只改一个变量做对照**：本轮先后试了「堆否定词」「换外套结构（拉链立领/无领）」共 6 张全部失败，
  最后定位到参考图才是根因。若一开始就把「参考图有无服装」作为唯一变量对照，2 张就能定论。
- **背景用「中等明度灰」而不是「中性灰」**：写「中性灰」时模型给的是接近白的浅灰（实测采样 216），
  此时**白衬衫(约240) 与背景差仅 24**，低于抠图阈值 → 白衬衫会被误抠出洞。
  写「中灰色（中等明度，不是浅灰不是白色）」后背景落到 128~160，白衬衫（差>80）与
  深色衣物（差>60）两向都能拉开，抠图才安全。
- **防版式坍塌**：偶发「大头 + 小人重叠」的诡异构图 → 提示词加「画面中只有一个人物、只有一个头部，身首比例协调，构图正常」，并换 seed。
- **透明背景（重要）**：⚠️ 本实例的云端抠图节点**全部不可用**——
  | 节点 | 结果 |
  |---|---|
  | `BiRefNetRMBG` / `RMBG` | ❌ 模型加载失败：`initialization of _pywrap_checkpoint_reader ...`（TF checkpoint 问题） |
  | `easy imageRemBg` | ❌ 要 HF gated 仓库 → 401 |
  | `Image Remove Background Rembg (mtb)` | ❌ 把 ComfyUI 整个搞挂（后续 `/system_stats` 持续 500） |
  | 本地 `pip install rembg` / `onnxruntime` | ❌ Tsinghua 源无包；官方 PyPI 被沙箱拦 |
  | 系统 `buddy-image-processing --operation matting` | ⚠️ 需敏感审批（本回合超时未授权） |

  #### ✅ 最终方案 = **青幕背景 + 色调判据抠图**（脚本 `<project>/story-wip/素材/matte_local.py`）
  > **一句话：背景用青色（cyan），抠图只判「色相」不判「亮度」。**

  **灰阶背景为什么全部被淘汰**（4 轮迭代踩出来的）：
  | 背景 | 结果 |
  |---|---|
  | 中性灰（实测模型给到 146~179） | ❌ 撞**白发/花白头发**(180~230) → 头顶被抠穿；也撞无彩灰毛衣 |
  | 深灰（约 47） | ❌ 撞**黑/深色衣物**(差仅~20) → 裤子/外套斑驳破洞 |
  | 「绿幕/chroma key」指令 | ❌ **Krea2 不理会**这个技术词，直接给白底 |
  ⇒ 灰阶背景**无解**：白发与黑衣分处亮度两端，任何灰阶明度都会撞中其中一端。

  **青幕为什么成立**：青色在任何人物元素（白发/灰衣/黑衣/藏青衣/棕衣/白人肤色/白衬衫）
  上「绿蓝都不显著高于红」。实测采样背景 `(94,159,169)`，各元素判据全部安全。
  唯一禁忌 = **青/绿色衣物**（本剧无）。

  ```python
  # 抠图判据（色调类，与明暗无关 → 天然容忍背景光照渐变）
  bgmask = (g - r > 20) AND (b - r > 20)          # 青色像素
  # 再 中值去噪 → 膨胀保连通 → 从四边 floodfill 只取「外围连通背景」
  #   （内部破洞自动填回；臂间缝隙上下开口仍连通 → 正确抠掉）
  # → 反相得人物 alpha → MinFilter×2 收缩去毛边 → GaussianBlur(0.8) 抗锯齿
  # → 青色 despill：r = max(r, min(g,b))  （去边缘青边）
  ```
  - ⚠️ **别用「逐通道亮度差」判据**：青幕有光照渐变时，明暗差异会漏判 → 背景残留斑块
    （实测左下角残留一块）。色相判据与明暗无关，才是稳的。
  - 提示词写法：`背景为均匀的纯青色背景（cyan，明亮的青蓝色），背景颜色完全均匀一致、无渐变、无纹理、无阴影、无杂物。`
  - 生成后**必须开图 + 看体积**（5~6KB = 单色空图，history 会谎报 success）。
  - 性质：**近似 alpha**（非 ML 发丝级），边缘略硬但干净可用；将来若 ML 抠图可用应替换。
  - 现成脚本：`gen_bust_cyan.py`（批量青幕出图）+ `matte_local.py`（`c:<角色id>` 走青幕抠图；
    `t:` = 纹理感知灰底、`g:` = 绿幕、无前缀 = 旧灰底）。

### 11.1 定稿配方（一句话）
**参考图 = default **已抠图的 RGBA 成品**（`Krea2_Bust_<char>.png`）**贴白底**后裁出的「头 + 颈」

提示词 = 构图比例（写在最前）→ 姿态（写在最前，仅姿态类）→ 身份锚 → 神态 → 服装 → 画布收尾。**

```python
# ① 参考图：底稿必须用「已抠图 RGBA 贴白」——gray 原图的背景可能是绿幕，会被画进成品
rgba = Image.open("Krea2_Bust_<char>.png").convert("RGBA")
im = Image.new("RGB", rgba.size, (255, 255, 255)); im.paste(rgba, (0, 0), rgba)
# 裁切高度 = 实测「肤色带底」（下巴）再 +24px，钳到 [0.26H, 0.34H]
bottom = min(0.34, max(0.26, (skin_bottom(im) + 24) / H))
head = im.crop((0, 0, W, int(H * bottom)))
# 放大贴白底 → 上传（文件名带 REF_VER）→ 作 image1（image1_tokens="high"）
# ② 提示词（顺序即权重，构图/姿态必须最前）
prompt = (

  "人物身体最宽处（含手臂与衣摆）约占画面总宽度的 80%；"      # ← default 实测值
  "人物的水平中心在画面水平中线附近（约 50% 处）；"
```

### 11.2 六条硬结论（每条都有对应的废图）

| # | 结论 | 反例 / 代价 |
|---|---|---|
| ① | **参考图只能含「头 + 颈」，绝不能含全身** | 喂整张 default 底稿 → Krea2 进入「重画整件衣服」模式，服装由它自己的**训练先验**决定；实测给「黑皮夹克 + 黑高领」补出**白衬衫领 + 白袖口**，还把无拉链翻领款画成拉链立领款。参考图里本来没白领。 |
| ② | **在提示词里禁止某个元素是无效功** | 写「绝不添加衬衫领，绝不出现白色衣领与白色袖口」→ 白领照旧。Krea2 的负向是 `ConditioningZeroOut`（零化），**不存在真正的负向词**；正向里写下「衬衫领」这些字反而**疑似反向提示**。把提示词里所有服装词（含否定句）删干净，白领照旧 → 证明根因在参考图不在文本。 |
| ③ | **参考图不能含"构图"信息，构图要用绝对比例写进提示词** | ① 写「保持参考图的构图、机位完全不变」→ 模型把头颈裁切图的构图当目标，输出**塌成头肩特写**；② 只写「从头到腰部完整入镜」→ 模型**自由决定人物大小**，4 张里 1 张塌、2 张人物偏小（头顶下移 4%~11%）。 |
| ④ | **构图比例段必须放在提示词最前面**，并写明"最重要" | 同一段文字放在**末尾**时，模型只当"参考"→ 人物仍偏小约 15%；**提到最前**后头顶漂移从 8.3% 降到 2.3%、宽度 80% 与 default 的 80% 完全吻合。 |
| ⑤ | **比例数字按角色各自量测，且要钳制** | 各角色 default 的头顶位置差很大（3.4% ~ 11.2%）。量测用**轮廓 bbox**（口径已验证：给 80% → 输出 bbox 就是 80%）。但要钳到 **[55, 92]%**：个别角色衣服下摆真的撑到 99%（x=4..765），原样写进去会诱导"贴边画"。 |
| ⑥ | **侧面 / 坐姿 / 半躺等"姿态变化"的任务，不要给宽度数字** | 宽度是"正面站姿"量出来的；90° 侧身的宽度天然只有正面一半，坐姿也不同 → 与姿态本身冲突。这类只锚「头顶高度 + 水平中心」。 |
| ⑦ | 🔴 **头颈裁切的"高度"不能写死 20%，要按实测肤色底定** | 307px 对**所有**角色都切在脸上（各角色肤色带底实测 25.7%~40.5%H）；**头更大/脸更长的角色直接丢脸** —— 实测 2 张输出**只有头发、脸完全没渲染**（体积偏小、`hf_energy` 比值 0.67~0.77）。改成「实测肤色底+24px，钳 [0.26,0.34]H」后同 seed 重跑，脸全部恢复。 |
| ⑧ | 🔴 **底稿必须用「已抠图 RGBA 贴白底」，不能用 gray 原图** | gray 原图的背景**可能是绿幕**；裁进参考图后模型把这片绿**画进成品**（画面正中一块绿矩形），且**事后抠图去不掉**（自动判底色只看四角，而四角是灰的）。 |
| ⑨ | **姿态约束写末尾 ≈ 没写，必须前置 + 写出反面** | `expr` 末尾写"姿态为半躺病床抬起身、左手抬起" → 出图是**站着的老人、双手下垂**。前置并写明"（不是站着的老人）"、补可验证细节（"双肩离开床面""下半身盖被子不可见"）才生效。 |
| ⑩ | **改了参考图逻辑必须抬「参考图版本号」** | 参考图按文件名在云端复用（`ref_exists` 命中就跳过上传）。改了裁切/底色却不换名 → **改了等于没改**。建议文件名带 `_v2` 之类版本后缀。 |

### 11.3 参考图量测工具（判定"是人物"的正确姿势）
```python
# ❌ 不能用「与四角背景色的色差」：底图背景是带噪点/渐变的浅灰，阈值一低整张图都判成人物
# ✅ 用亮度：取边框像素亮度中位数当 bg，凡 lum < bg-38 即人物
border = [边界像素亮度]; cut = median(border) - 38
```

⚠️ **但亮度法有个前提：底稿与差分的背景"色型"必须一致。** 本项目实测翻车：
底稿是**绿幕**（四角 RGB(65,133,73)，亮度中位只有 116），阈值 `116-38=78`
把**大片绿幕也判成人物** → 宽度虚高到 0.94~0.98；而它的差分是浅灰底 → 真实宽度 0.71。
两者一比就是"宽 0.94→0.73"，**看着像构图塌了，其实是量测被背景色型污染**（裁掉 16px 边框也救不回来）。

✅ **正解：先抠图，再用 alpha 通道量。** alpha>128 即人物，**跨背景完全可比**：

```python
def alpha_bbox(png_path):          # 抠图后的 RGBA
    im = Image.open(png_path)
    if im.mode != "RGBA": return None
    return im.split()[-1].point(lambda v: 255 if v > 128 else 0).getbbox()
```

> **一张图就能同时判定"白领复发"与"构图是否塌"**，比逐张开 22 张开图快得多。

### 11.5 重跑纪律
- **换前缀 + 换 seed 才是一次真新跑。** 同前缀重跑时云端会出现
  「几秒返回、落盘字节与上一轮完全一致」的**旧产物复用**，
  会让你误判"改了提示词没效果"。建议在脚本里用具名版本号（`RUN_TAG = "A".."H"`）留存迭代历史。
- **参考图另有独立的版本号**（见 11.2 ⑩），两者都要换。
- 🔴 **不要并发跑两批云端任务。** 并发时后提交的那批会 `find_output` **超时 600s 报"无产物"**，
  但**云端其实已经出图了**（`/history` 里 `status=success`、`outputs` 齐全）。
  补救：按 prefix 扫 `/history?max_items=N` 找到文件名，**直接按文件名 `download` 下载**。
  宁可串行等，也别并发。
- 🔴 **被杀掉的后台任务会在云端留一个"孤儿任务"。** 中断脚本后必须先查 `/queue`：
  若 `queue_running` 里还挂着那张图，**等它跑完再提交下一批**，
  否则下一批的首张会被它顶掉、撞上 600s 超时。开批前加一段"等队列排空"的轮询最稳。

### 11.6 🔴 `ref="side"` 时，**姿态文字里不能出现"挡住/看不见"**（2026-09-16 实测）
**症状**：给卧床老人出 90° 侧脸（`ref="side"`，用资产表侧面列当参考图），
姿态写「上半身侧对镜头，头转向正侧面；**双肩以下被一床白色病床被子挡住，看不见手臂与下半身**」
→ 输出是**头肩特写**：头 + 一点肩，其余 70% 画面是空的透明区。

**根因**：模型把**任何"截断类"描述当成裁切指令**。写了"双肩以下看不见"，
它就真的在肩以下切掉。这与 §11.2 "构图/姿态必须前置"是同一枚硬币的两面 ——
前置的姿态文字权重高，**写得偏一点也会被严格照做**。

**对照事实**：同一批里 `zhouyu_side`（`ref="side"`、`pose=True`、**完全没有 `pose_text`**）
出的是**完整的、到膝盖的侧身立绘**。⇒ 差别只在那段姿态文字。

**对策**：
1. 姿态必须写**"什么完整可见"**，不写"什么看不见"：
   ✅「侧身而坐，**双肩、手臂与整个上半身都完整入镜**；从腰部往下被被子盖住，画面最下缘就是那床被子」
   ❌「双肩以下被被子挡住，看不见手臂与下半身」
2. **最稳的做法是干脆不写 `pose_text`** —— 只留 `SIDE_VIEW`（"严格 90 度正侧面"）+ `frame_for(pose=True)`。
   非正面机位的机位信息已经由 `SIDE_VIEW` 给足了，额外加姿态只会引入风险。
3. 拿不定时**两个变体一起跑、人眼二选一**（成本低，比反复改提示词猜快）。

### 11.7 🔴 两个"把人物画大"的系统性成因（2026-09-16 实测，都必踩）

**先立一条规范**（本作 20 张已落位立绘实测）：**`top`（轮廓最上行 / 画面高）必须落在 `3.5% ~ 10%`**。
超出这个区间，换图时角色就会突然"变大"或"变小"。
量测脚本直接用 alpha 通道：`素材/measure_sprite_frame.py`。

#### 成因 ① 用亮度法量**浅色头发** → `head_pct` 虚高 → 提示词把人写低
`measure_default()` 原本在 `Krea2_Bust_<base>_gray.png` 上用"亮度阈值"找轮廓。
**陆振声是白发**，底稿背景本身也是带噪点的浅灰 → **头发被漏检**，
bbox 顶边被推到眉毛以下 ⇒ `head_pct` 从真实的 **6.6% 虚高到 11.2%**。
这个数字被原样写进提示词（"头顶位于画面上缘往下约 11% 处"）→ 输出实测 `top = 25.8%`。

✅ **修法：改用已抠图 RGBA 的 alpha 通道量轮廓**（与发色 / 底色完全无关），
灰底稿 + 亮度法只作为兜底。修后：陆振声 11.2→**6.64**、周聿 5.47、陆昭 3.39、江砚 5.34，
与落位图实测一一吻合。
> **口诀：凡是要"量人物"的地方，第一选择永远是 alpha 通道；底色稿+亮度只在没有抠图时才用。**

#### 成因 ② `ref="side"` 的参考图是"只有一颗头"的方图 → 模型照搬它的构图
侧面参考图（`side_head_ref` 产物）是一张 696×640 的方图，**头占满了整块画布**。
模型的构图先验被这张图带跑 → 输出"大头特写"（实测 `top` 25.8% / 29.4%，
两版都没修好，即使去掉了 `pose_text`）。

✅ **修法：在构图段里加一条 `SIDE_GUARD`**，明说参考图只是头像、不代表构图：
```
⚠️ 参考图只是一张「头像」局部，仅用于确定脸型、发际线、肤色与侧面角度，
它不代表画面的构图与人物大小，也绝对不要把它按原样放大、铺满画面；
不要输出大特写、不要头肩特写。人物必须从头到腰部以下完整入镜，整体偏小、留出四周边距。
```
⚠️ 附带的可疑项（本轮一并改掉）：`outfit` 描述里**要提下半身**。
对比 `zhouyu_side`（outfit 写了"深色西裤"、构图正常）与失败的 `luzhensheng_side`
（outfit 只有上半身）—— 只写上半身时模型更容易只画上半身。

> **元教训**：出图不合格时，**先量数字、再猜原因**。
> 这一轮如果只靠"看图觉得头大了"去反复改提示词，大概率还在原地打转；
> 是 `measure_sprite_frame.py` 给出的 `top%=25.8 vs 规范 3.5~10` 把问题钉死的，
> 再用 `measure_default()` 打印出 `head_pct=11.2` 才找到真正的代码级根因。

### 11.8 🔴 侧脸只能用"资产表侧面列"当参考图 —— 换正面裁切会退化成"复制正脸"
**一次单变量验证的反面结论**（2026-09-16，`luzhensheng_side5`）：
把参考图从「资产表 90° 侧面列裁头」换成「default 底稿裁头+颈（**正面**）」，
其余一切不变（仍然写 `SIDE_VIEW`"严格 90 度正侧面"，仍然有 `SIDE_GUARD`）：

```
输出 = 参考图那张正面头像被原样贴进画面中央，连参考图自己的白底方框都画了进去
top% = 20.1、bottom% = 66.7（明显低于规范）
```

⇒ **模型不会"照文字把正面转成 90°"**，它更倾向于**直接复刻参考图的内容**。
这正是 §文件头「坑 2 · 把参考图当画面内容画进去」的同一失效模式。

**结论（写成规则）**：
| 要出的机位 | 参考图必须用 | 不能用 |
|---|---|---|
| 正面 | default 底稿裁「头+颈」（`ref="busthead"`） | — |
| **90° 侧面** | **资产表侧面列裁头（`ref="side"`）** | ❌ default 正面头颈裁切 |
| 背身 | 资产表背面列裁头 | ❌ 正面/侧面裁切 |

⚠️ 另外：`SIDE_VIEW`（"严格 90 度正侧面"）原本**只在 `ref="side"` 时注入** ——
一旦换参考图来源，机位指令会被静默丢掉（出的必是正面）。
✅ 已把它与参考图来源**解耦**成独立开关 `side_view=True`，避免这个隐蔽的接线错误。

## 十二、出「CG / 插画」（场景 + 人物双参考图）（2026-09-15 雾港回声 8 张实战）

CG 与立绘差分的处境**相反**：立绘可以"物理剔除场景"（参考图只给头颈），
但 CG 的场景**必须在场**（否则场景漂移），于是只能靠**调 token 权重**来压制。

### 12.1 定稿配方（一句话）
**顺序 `[场景, 人物]`；权重 `[low, low]`；构图（景别+机位+主体占比）写在提示词最前面并标「最重要」。**

```python
# Krea2EncodeRebalance: image1=场景参考图, image2=人物参考图
nodes["..."] = Krea2EncodeRebalance(
    text=pos_prompt, clip=..., vae=...,
    image1=scene_ref, image1_tokens="low",    # ← 🔴 关键：不是 high
    image2=char_ref,  image2_tokens="low",
)
# 人物参考图仍取「头 + 颈」裁切（同 §11），服装完全由文字描述
pos_prompt = (
  "这是一张游戏全屏插图，构图按以下要求（最重要，必须严格满足）："
  "<景别（如中景/近景）+ 机位（如俯拍/机位在门口）+ 主体在画面中的位置与占比"
  " + 背景占画面的比例（如天空/水面占上方三分之二）>。"
  "保持场景参考图里的空间结构、道具位置、光照方向与色调。"    # 场景职责
  "保持人物参考图里人物的脸型、五官、发型、肤色不变。"          # 人物职责
  "<画面内容：谁、在哪、做什么、什么动作>。<服装描述>。"
  "画面中只有一个人物。不要报纸标题、招牌、标语、标签、印章、手写字、门牌。"  # 见 12.3
)
```

### 12.2 五条硬结论（每条都有对应的废图）
| # | 结论 | 代价 |
|---|---|---|
| ① | **场景参考图给 `image1_tokens=high` → 必废。** 模型把参考图当"画布"照抄，输出变成"重新渲染的背景图"，CG 专属内容全丢（cg_01 六封信 → 桌上没有信；cg_02 → 没有人） | 8 张废图 |
| ② | **只把构图提到提示词最前、不改 token 权 → 压不住。** 前置文案对 `high` 的场景参考图无效 | 1 张探针 |
| ③ | **场景 token 降到 `low` → 成功。** 前置构图才生效，模型改为"按文字重新组织画面" | — |
| ④ | **`normal` 档不够。** 仍保留"抄参考图"倾向 → 画面退回大远景（台灯缩到角落、主体淹在杂物里）。**直接用 `low`，别试 normal** | 1 张探针 |
| ⑤ | 🔴 **写在提示词末尾的"负向约束"压不过场景参考图。** 参考图里有的东西，末尾写"不要 XX"基本无效 | 多张 |

**关于 ⑤ 的三次独立验证**（2026-09-15~16）：

| 负向约束（都写在末尾） | 参考图里确实有 | 结果 |
|---|---|---|
| "画面里不要出现任何可读或不可读的文字…" | 报纸标题 / 招牌 | ❌ 照抄（报纸出现乱码汉字、废墟出现「Lighthouse 灯塔」蓝招牌）|
| "不要拼图、不要多格、不要并排对比" | —（诱因是正文的物件枚举） | ❌ cg_05 照样出多格拼版 |
| "海面空空荡荡，没有任何船只" | 江面上的船 | ❌ cg_08 仍有一条船 |

⇒ **对策：负向约束必须放进 `FRAME_HEAD`（构图段、提示词最前），与正向构图写在一起。**
末尾只保留"锦上添花"型的收尾（画幅性质、背景替代说明），不要指望它压制参考图。
> 这条与 §11.2"构图/姿态必须前置"是**同一条原理的负向版本**：
> **前置 = 权重高 = 说得上话；末尾 = 权重低 = 形同建议。**

> 与 §11 是同一条原理：**谁"像画布"谁拿低权**。立绘用"参考图只给头颈"物理剔除，
> CG 场景剔除不了 → 只能降权。

### 12.3 场景参考图里的文字会被抄进画面
提示词写"不要文字"**没用**（参考图里本来就有字）。要改成**具体物件清单**：
"不要报纸标题 / 招牌 / 标语 / 标签 / 印章 / 手写字 / 门牌"。
（cg_02 曾被抄进一块"Lighthouse 灯塔"蓝招牌。）

### 12.4 顺序/权重的三种错误组合（A/B 探针实测）
| 顺序 | 权重 | 结果 |
|---|---|---|
| 【人物, 场景】 | 【high, *】 | 场景里被画进**一颗巨大模糊的人头** |
| 【人物, 场景】 | 【low, high】 | **人物彻底消失**，只剩场景 |
| 【场景, 人物】 | 【high, high】 | 人物在，但 CG 内容全丢（见 12.2 ①） |
| **【场景, 人物】** | **【low, low】** | ✅ **正确** |

### 12.5 🔴「物件集合型」CG 会输出**多格拼版**（2026-09-16 实测，**单参考图也触发**）
**症状**：要"桌面上摊满 5 种物证"的 CG，出来 1920×1080 但**左侧约 19% 是一块灰底 + 一张
局部小插图**，其余才是正图 —— 典型"版式化/拼贴"输出。

**检测（比开图快）**：纯 PIL 算**列均值**，看相邻列跳变：
```python
cols = [mean(pixel[x, ::8]) for x in range(0, W, 8)]
jumps = [abs(cols[i]-cols[i-1]) for i in range(1, len(cols))]
# 跳变 > 25 且只出现在一条固定 x 上 ⇒ 硬竖边 ⇒ 拼版伪影
```
实测该废图在 `x=384` 处跳变 **134.5**；同期正常图**零命中**。

**根因（推定）**：提示词把画面内容写成**要展示的物件清单**——
"方格纸信纸、一张烧焦边缘的硬纸卡片、几张翻拍的纸质表格、一个牛皮纸档案袋、一本复印的旧账本"，
模型理解成"这 5 样都要展示出来" → 排版成主图 + 小图。

**对策**：
1. **改成整体场景描述**，不枚举：「桌上摊着几摞散乱的纸和一个牛皮纸档案袋」；
   真要逐样清楚，交给 **`item` 物件弹窗**（§见 `avg-game-maker` 的 P3），别塞进一张 CG。
2. `FRAME_TAIL` 补上**版式类负向**：「不要局部放大图、不要小图、不要插图框、不要分栏」。
   ⚠️ 注意与 12.3 的区别：12.3 的"具体物件清单"是**禁止清单**（不要出现什么），
   本条讲的是**内容枚举**（要出现什么）—— 后者会诱发排版，前者不会。
3. **负向词也要前置**：`FRAME_HEAD` 里加「整张画面是同一个空间里一次拍摄的连续照片，
   不是拼图、不是多格、不是分镜格、不是图文目录」。理由同 §11.2 / 12.2：
   写在末尾的约束会被参考图压过去，只有前置才压得住。

### ✅ 12.5.1 修法已验证（2026-09-16，cg_05 重出）
同一条 prompt、同一张场景参考图，只做上述三处改动（正文去枚举 + 负向前置 + 尾部加版式负向），
换前缀（`CG7_`）+ 种子 +700 重出，结果：
```
改前 CG6_CG2_OFFICE_EVIDENCE:  colEdge=70.0@x=379  flat=27格(最大连通27)  mean=72.1  ← 拼版
改后 CG7_CG2_OFFICE_EVIDENCE:  colEdge=10.0@x=365  flat= 0格(最大连通 0)  mean=45.1  ← 单幅连续
```
肉眼复核：拼版消失，画面变成一张连续的深夜报社交景（层层叠叠的纸堆 + 绿罩台灯 + 雨夜窗），
且整体变暗（mean 72→45），更贴"整层办公室都暗着"的设定。**结论：三处改动同时有效。**

**⚠️ 附带的检测脚本 bug（已修）**：算列均值跳变的峰值时，`sorted(range(len(d)), key=...)[:3]`
拿到的是**按值降序的前 3 个下标**，取峰值必须用 `d[top[0]]` 而**不是** `d[max(top)]`
（后者取的是"下标最大的那个"，会把真实峰值 70 显示成 3）。
此坑曾让我一度以为 cg_05 的硬边很小 —— 是靠同时打印 top3 的自检输出才发现的。
**教训：报警脚本要连原始 top-N 一起打印**，否则阈值判断错了也看不出来。

### ⚠️ 12.5.2 硬边**单独出现不算废**，必须与"大片纯色块"同时命中
玻璃幕墙竖框、门框、地平线都会给出 30~45 的列/行跳变（cg_08 商业广场实测竖边 42.0@x=988
是幕墙分格，画面完全正常）。拼版的真正签名是 **硬边 + 连通纯色块**：
```python
panel = (colEdge > 30 or rowEdge > 42) and (最大连通纯色格数 > 4)
```
纯色块统计要**排除顶部 3 行（天空）与底部 2 行（暗角）**，否则天空/暗角会全程假阳性。
