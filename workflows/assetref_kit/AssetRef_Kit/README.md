# 资产参考图工具包（Asset Reference Kit）

> 给 AI / 用户的操作手册。**目的**：为同一个场景产出"多角度参考图"，
> 供后续**故事出图**时反复喂给模型，避免同一场景在不同画面里结构、道具、光照、色调漂移。
>
> 本工具包提供 **两种**产出方式，二选一。下方 §2 给出选择依据，§3 给出运行方式，§5 给出必坑与客观校验方法。

---

## 0. 一句话结论

- **方式 A（2×2 网格图）**：一张 1536×1536，内部 2×2 排布同一场景 4 个视角。适合"一张图锁定全场景 + 4 个大概角度"。
- **方式 B（超宽连续视角图 + 裁 4 段）**：一张 3072×1024 超宽连续场景，裁成 4 段当 4 张独立角度参考。适合"4 张清晰、各异、可客观验证"的角度参考。
- 两者**都不是真 360° 等距全景**（见 §5 必坑 3）。krea2 是平面扩散模型，出不了可环视的真全景。

---

## 1. 使用前提

1. ComfyUI 已在本机启动：`http://127.0.0.1:8188`。
2. 已加载以下模型（文件名需一致）：
   - UNET：`krea2_turbo_int8_convrot.safetensors`
   - CLIP：`qwen3vl_4b_fp8_scaled.safetensors`（`type=krea2`）
   - VAE：`qwen_image_vae.safetensors`
3. Python 环境可 `import PIL`（裁剪/哈希校验需要）。

若不确定是否就绪，先运行 `method_pano.py` 或 `method_2x2.py`，脚本会直接提交到 8188；报错即说明环境未起。

## 2. 两种方式对比与选择

| 维度 | 方式 A：2×2 网格图 | 方式 B：超宽连续视角图 |
|---|---|---|
| 单张产出 | 1 张（内含 4 格） | 1 张宽图 + 自动裁 4 张 |
| 画布 | 1536×1536 | 3072×1024，裁 768×1024×4 |
| 4 视角是否真不同 | 同 seed/同 DNA，**结构强一致**；但视角是"示意"非真三维 | 客观验证为不同视角（哈希差 ~30%） |
| 透视/畸变 | 4 格各自独立，无长条拉伸 | 连续投影，**无极点畸变、色调无突变** |
| 色调一致性 | 强（同一 latent 一次生成） | 强（连续空间天然统一） |
| 缺陷 | 相邻格可能互相"渗透"（道具跨格串位）；每格小、细节少 | 不是真 360，覆盖不到"相机背后"半圈 |
| 给故事出图当参考 | 一张图当整体 reference | 4 张分别当不同机位 reference |
| 生成耗时 | 约 5 分钟 | 约 5 分钟 + 裁切（秒级） |

**怎么选（给 AI 的判断流程）：**
- 用户要"一张图快速看全场景 + 4 角度" → **方式 A**。
- 用户要"4 张清晰、独立、互不相同的角度参考，且要客观证据" → **方式 B**。
- 用户要"真 360° 四壁环绕" → 两种方式都做不到，明确告知并建议 3D/全景模型（§5 必坑 3）。
- 用户没偏好 → 默认 **方式 B**（客观可验证，且色调/畸变最稳）。

**最终让用户确认选哪个，再执行对应脚本。**

## 3. 运行方式

### 方式 A：2×2 网格图
```bash
# 1) 编辑 method_2x2.py 顶部 SCENE_GRID（想锁定的场景 + 4 视角描述）
# 2) 运行
python method_2x2.py
# 产出：ComfyUI/output/SceneGrid/<名字>_2x2_00001_.png
# 脚本自动校验 4 个象限哈希差，打印是否真的不同视角
```

### 方式 B：超宽连续视角图
```bash
# 1) 编辑 method_pano.py 顶部 PANORAMA 提示词（连续场景描述）
# 2) 运行
python method_pano.py
# 产出：ComfyUI/output/Panorama/<名字>_00001_.png（宽图）
#       ComfyUI/output/Panorama/<名字>_front/right/back/left.png（4 张裁切）
# 脚本自动打印 4 段两两哈希差，用于客观确认"确为不同视角"
```

> 两种脚本都内置"轮询 history 直到完成"逻辑，跑完会自动打印 `DONE` 与哈希差，无需手动盯。
> 生成中可在 ComfyUI 网页 `http://127.0.0.1:8188` 的 output 目录实时看到图片。

## 4. 给后续故事出图怎么用（关键）

产出的参考图**不是最终图**，是"给模型的约束"。喂图方式：
- 方式 A：把整张 2×2 图作为单张 reference 附在故事出图提示词里，并文字注明"四角分别对应主视/左/右/俯视"。
- 方式 B：故事出图时，按该镜头的机位选对应那张（front/right/back/left）当 reference。
- 两者都要**同时附上同一段 Scene DNA 文字**（见 `提示词模板.md`），双保险锁一致性。

## 5. 经验与必坑（完整证据见 `经验与必坑.md`）

1. **必坑：逐张角度（单参考图 img2img）会全部锚成同一视角。**
   测得与主视角哈希差仅 4–10%（CAM04 9.7%、CAM03 7.5%、CAM09 立面 4.5–5.2%），文本角度指令被模型忽略。
   → 不要想靠"一张参考图 + 改文字角度"出多角度套图。用本工具包的 A 或 B。
2. **必坑：夜景/日景"同机位改提示词"往往不变亮。**
   测得平均亮度全卡在 132–137（白天 CAM01=134.4，"夜景" CAM08=132.3，几乎一样）。
   → 真要昼夜差异，需换参考图或强提示+对比约束，且务必用"平均亮度"客观确认。
3. **必坑：krea2 出不了真 360° 等距全景。**
   平面扩散模型做等距柱状必极点畸变、左右接缝难处理。本工具包方式 B 是"超宽连续视角图"，**不是 360**，请勿误称。
   真 360 需 3D 模型（本环境 Hunyuan3D 因 TF 损坏不可用）或专用全景模型。
4. **必坑：反打视角的光照方向不会自动翻转。**
   模型只改色调不改结构，CAM02 亮度与 CAM01 一致即证据。
5. **经验：宽图别太宽。** 3072×1024 是较稳的宽比；再宽（如 4096+）边缘物体易被拉伸。
6. **经验：seed 必须固定**才能复现；批量必须同一段 Scene DNA 逐字复制。
7. **经验：客观校验不可省。** 用平均哈希差确认 4 段/4 格确为不同视角；用平均亮度确认昼夜真变化。脚本已内置。
